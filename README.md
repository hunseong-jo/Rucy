# 루시 — 나만의 AI 비서

Gemini(무료) → Groq(무료) → 로컬 Ollama 순서로 **두뇌를 갈아끼울 수 있는** 개인 비서.
무료 서비스가 종료돼도 로컬 모델이 받쳐주기 때문에 비서 자체는 계속 작동합니다.

## 이름 바꾸기

`config.json`의 **`"name"` 한 줄**이 전부입니다. 여기만 고치면 시작 화면, 대화 기록,
그리고 모델이 자기를 소개하는 말(`persona`의 `{name}`)까지 한꺼번에 따라 바뀝니다.

```json
"name": "루시",
```

## 실행

`start.bat` 더블클릭. (또는 터미널에서 `python agent.py`)

종료는 `exit` 입력.

### 로컬 전용 모드 (프라이버시)

```
python agent.py --local
```

외부로 아무것도 보내지 않고 로컬 Ollama만 씁니다. 인터넷이 없어도 작동합니다.
민감한 내용(개인정보, 공개 전 기획서 등)은 이 모드로 다루세요.

## 다른 PC로 옮기기

**`my-agent` 폴더를 통째로 복사하면 끝입니다.** 코드·설정·키·기억이 전부 이 안에 있고,
오늘까지의 대화를 기억한 채로 이어집니다. 새 PC에 미리 있어야 하는 건 둘뿐입니다.

| | 없으면 |
|---|---|
| **파이썬** (필수) | 아예 안 켜집니다. `pip install`은 여전히 필요 없습니다 |
| **Ollama** (선택) | 최후의 보루(로컬 모델)와 기억 검색(임베딩)이 빠집니다. 나머지는 작동 |

옮긴 뒤 **`setup_check.bat`** 을 더블클릭하면 뭐가 빠졌는지 알려줍니다.
파이썬·Ollama·모델·API 키를 확인하고(키는 실제로 한 번 호출해서 살아있는지 봅니다),
없는 건 설치 링크나 `ollama pull` 명령까지 찍어줍니다. 네트워크 없이 파일만 볼 땐 `--offline`.

> ⚠️ `keys/` 폴더엔 **API 키 원문이 그대로** 들어 있습니다. 클라우드나 공용 PC로 옮길 땐 빼세요.
> 음성 입력은 윈도우 전용입니다(녹음에 winmm을 직접 호출).

계산하므로 `eval()`처럼 코드가 실행될 위험이 없습니다.

## 일꾼 모드: `/일 <시킬 일>` — 스스로 끝까지

평소의 루시는 **한 번의 문답**입니다. 도구를 몇 번 쓰고 답이 나오면 끝입니다. 그래서
"자료 찾아서 정리하고 문서로 만들어 줘"처럼 단계가 여럿인 일은 중간에서 만족하고 멈춥니다.

일꾼 모드는 그 위에 얹는 **바깥 루프**입니다.

```
계획 세우기 → [ 한 단계 실행 → 스스로 검증 → 아니면 다시 ]×N → 최종 보고
```

```
나 > /일 최근 AI 뉴스 3개 찾아서 요약하고 바탕화면에 워드로 저장해줘

[일꾼] 2단계 계획:
    1. 웹에서 최근 AI 뉴스 3건의 제목·요약·출처 링크를 확보한다
       (끝난 기준: 기사 URL 3개를 실제로 확보했다)
    2. 요약을 워드 문서로 만들어 바탕화면에 저장한다
       (끝난 기준: Desktop\AI뉴스.docx 파일이 실제로 만들어졌다)
[일꾼 1/2] ...
[일꾼 1/2] 아직 안 끝났습니다 — URL이 기사가 아니라 카테고리 페이지입니다
[일꾼 1/2 (재시도 1)] ...
[일꾼 1/2] 확인 완료
```

핵심은 **검증**입니다. 모델은 "다 했습니다"라고 말하는 데 아무 저항이 없어서, 시키지 않으면
파일을 안 만들어 놓고도 만들었다고 합니다(실제로 겪었습니다). 그래서 단계마다 **다른 턴**에서
"완료 조건이 실제로 충족됐는가"를 도구가 돌려준 근거와 대조해 판정하고, 아니면 이유를 알려주며
다시 시킵니다. 그래도 못 끝내면 **끝내지 못했다고 정직하게 보고합니다** — 실패 사실만은
모델의 말과 무관하게 코드가 덧붙이므로 지어낼 수 없습니다.

각 단계는 자기만의 짧은 대화에서 돕니다(한 대화에 다 쌓으면 컨텍스트 한도를 넘겨 죽습니다).
본 대화에는 목표와 최종 보고만 남으므로, 일이 끝난 뒤 "아까 그거 어디 저장했지?"가 이어집니다.

`config.json`의 `worker`로 상한을 둡니다: `max_steps`(6) · `retries`(2) · `max_minutes`(12).
단계마다 모델을 2번 이상 부르므로 무료 한도를 평소보다 빨리 씁니다.

## 내 PC 문서 전체 검색

"작년에 쓴 그 계약서 어디 있지?" — 파일명을 몰라도 **내용으로** 찾습니다.
바탕화면·문서·다운로드의 PDF·워드·엑셀·PPT 속 글자까지 뒤집니다.

지식 창고(`knowledge/`)와는 다른 물건입니다:
- **지식 창고** = 내가 **골라서 넣은** 자료(강의 PDF·프로젝트 노트). 의미 검색(임베딩).
- **문서 검색** = 내 PC에 **이미 널려 있는** 파일들. 넣은 적 없어도 찾아냅니다.

임베딩을 쓰지 않습니다. 파일 수백 개를 전부 임베딩하면 색인에 수십 분이 걸리고 질문마다
Ollama를 깨워야 하는데, 파일 찾기는 대개 낱말로 충분합니다. **282개 문서 색인에 0.4초,
검색 0.016초**입니다. 색인은 증분이라 두 번째부터는 바뀐 파일만 다시 읽습니다.

- 처음 검색할 때 알아서 색인합니다. `refresh_hours`(24)마다 자동 갱신합니다.
- `/문서색인`으로 지금 갱신하고, `/문서색인 전체`로 처음부터 다시 읽습니다.
- 범위는 `config.json`의 `filesearch.roots`로 늘립니다.
- 구버전 `.doc`/`.xls`/`.hwp`는 파서가 없어 못 읽습니다.

## 메일·캘린더 (구글 연동)

"안 읽은 메일 요약해줘", "이번 주 일정 뭐 있어?", "다음 주 화요일 2시에 치과 넣어줘"

권한을 **일부러 좁게** 잡았습니다:
- **메일 = 읽기 전용.** 루시가 사용자 이름으로 메일을 보내는 건 되돌릴 수 없는 일입니다.
- **캘린더 = 읽기 + 쓰기.** 일정은 잘못 넣어도 지우면 그만이라 위험이 훨씬 작습니다.
  그래도 넣기 전에 `y/N`로 확인받습니다.

**설정 (한 번만, 5분):**
1. [구글 클라우드 콘솔](https://console.cloud.google.com/)에서 프로젝트 만들기
2. 'API 및 서비스' → 라이브러리 → **Gmail API**와 **Google Calendar API**를 각각 '사용'
3. 'OAuth 동의 화면' → 외부 → 앱 이름·이메일 채우고 저장 → **본인 이메일을 '테스트 사용자'로 추가**
   (이걸 빼면 로그인이 거부됩니다)
4. '사용자 인증 정보' → 'OAuth 클라이언트 ID' → 유형은 반드시 **데스크톱 앱**
5. 내려받은 JSON을 `keys/google_credentials.json` 으로 저장

그다음 "메일 확인해줘"라고 하면 브라우저가 열립니다. **'허용'을 한 번 누르면 끝**입니다
(토큰이 저장돼 그다음부터는 조용히 갱신됩니다).

## 어려운 질문은 더 깊이 생각합니다

`config.json`의 `deliberate`로 켜고 끕니다. **어려운 질문일 때만** 작동하므로 평소 속도는 그대로입니다.

- **계획** — 답을 쓰기 시작하기 전에 "무엇을 어떤 도구로 확인할지" 먼저 정하게 합니다 (추가 호출 없음)
- **검토** — 답을 내보내기 전에 도구가 가져온 근거와 대조해 스스로 감수합니다. 지어낸 사실이나
  계산 실수가 있으면 고쳐서 내보냅니다 (모델 호출 1회 추가)

## 그림 그리기 (하이브리드 2단계)

GTX 1650의 **VRAM 4GB로는 Flux를 로컬에서 못 돌립니다.** 그래서 역할을 둘로 나눴습니다.

| | 어디서 | 무엇을 |
|---|---|---|
| **1단계 `draw`** | 온라인 Flux (Pollinations, 무료·키 불필요) | 구도·손가락·글자가 멀쩡한 뼈대. **내 GPU 연산 0**, 3초 |
| **2단계 `restyle`** | 로컬 SD 1.5 WebUI (img2img) | 내 병합 화풍으로 덧칠. `denoising 0.35`라 구도는 유지 |

그냥 "고양이 그려줘"라고 하면 루시가 알아서 **영어 상세 묘사로 옮겨** 그리고 바탕화면에 저장합니다.
"내 화풍으로 바꿔줘"라고 해야 2단계가 돌아갑니다.

**WebUI가 꺼져 있어도 그림 기능은 죽지 않습니다.** 1단계 결과가 그대로 최종본이 되고, 켜는 법을
안내합니다. 2단계를 쓰려면 `webui-user.bat`의 `COMMANDLINE_ARGS`에 이렇게 넣고 실행하세요:

```
--medvram --xformers --api
```

`--api`가 없으면 루시가 접속할 수 없습니다. 설정은 `config.json`의 `image` 블록에 있습니다.

> Pollinations는 확장자가 `.png`처럼 보여도 실제로는 **JPEG**를 돌려줍니다. 그래서 파일 헤더를 보고
> 확장자를 정합니다 — 잘못 붙이면 2단계에서 깨집니다.

## 눈 (이미지 보기)

스크린샷·사진 경로를 질문에 섞으면 그대로 보여주며 물어볼 수 있습니다.

```
나 > C:\Users\user\Desktop\에러.png 이거 무슨 오류야?
나 > /보기 스샷.png 이 UI에서 어색한 부분은?
나 > 이 그림에서 왼쪽 위 버튼은 뭐야?     ← 경로를 다시 안 적어도 방금 그 그림을 다시 봅니다
```

파일명만 적어도 바탕화면·사진 폴더·홈에서 찾아봅니다. 존재하지 않는 파일명(예: `food.onnx 어디 있어?`)은
평범한 대화로 취급하고 무시합니다.

**눈이 달린 두뇌에만 보냅니다** (`config.json`의 `"vision": true`). 눈 없는 모델에 이미지를 보내면
400으로 거절하거나, 더 나쁘게는 **이미지를 무시하고 지어냅니다**.
2026-07-12 실측: Groq qwen3.6-27b(0.7초)·Gemini 계열 = 가능 / Cerebras·qwen3-32b·OpenRouter·로컬 = 불가.

두 가지 함정을 코드에서 막고 있습니다:
- 이미지가 실린 요청에 **도구 명세까지 함께 실으면 거절**하는 모델이 있어, 보는 턴에는 도구를 끕니다.
  (그림을 보고 한 설명은 대화에 남으므로, 이어지는 질문에서는 평소대로 도구를 씁니다)
- **이미지는 딱 한 턴만 삽니다.** 대화에 남겨두면 매 요청마다 base64 수 MB가 다시 실려 토큰 한도를 태우고,
  눈 없는 모델이 `content must be a string` 400으로 전부 거절합니다.

## 화면 보기

파일로 저장된 그림만이 아니라 **지금 모니터에 떠 있는 것**을 봅니다.

```
나 > 지금 화면 좀 봐줘. 이 에러 무슨 뜻이야?
나 > /화면 이 UI에서 어색한 부분은?        ← 확실하게 찍고 싶을 때
나 > 지금 이 창만 봐줘                      ← 맨 앞 창 하나만
```

- **찍기 전에 3초 기다립니다**(`config.json`의 `screen.delay`). 터미널에서 말을 걸면 맨 앞 창은
  루시의 콘솔이라, 바로 찍으면 보여주려던 창 대신 루시 자신을 보게 됩니다. 그 사이에 창을 띄우세요.
- 기본은 **맨 앞 창이 있는 모니터 한 대**만 찍습니다. 듀얼 모니터를 한 장에 담으면 3840px가 1920으로
  줄면서 글자가 뭉개져 오류 메시지를 못 읽습니다. 둘 다 보려면 "모니터 둘 다 봐줘".
- 찍은 그림은 눈(vision) 흐름을 그대로 타므로, 눈 달린 두뇌에게만 갑니다.

## 문서 만들기

읽기(`read_document`)의 반대쪽입니다. 오피스 파일은 결국 **정해진 XML을 담은 zip**이라
python-docx·python-pptx 없이 표준 라이브러리만으로 만듭니다.

```
나 > 알약 게임 도구 4종 설명하는 PPT 3장짜리로 바탕화면에 만들어줘. 발표자 노트도 넣어줘.
나 > 이번 주 지출을 표로 정리해서 엑셀로 저장해줘
```

루시는 내용을 마크다운으로 씁니다 — `# 제목`이 PPT에서는 **새 슬라이드**, 워드에서는 큰 제목이 되고,
`노트:`로 시작하는 줄은 발표자 노트가 됩니다. 엑셀은 마크다운 표나 CSV로 받습니다.
파일을 만들기 전에 항상 확인을 받습니다.

⚠️ **파워포인트 함정**(오래 헤맴): 미니멀 노트마스터를 끼우면 파워포인트가 파일 전체를
"손상되었습니다"로 거부합니다. 노트마스터 없이 notesSlide만 두면 잘 열리고 노트도 보입니다.
`[Content_Types].xml`은 zip의 첫 항목이어야 합니다.

## 예약: 알림과 지시

예약은 두 종류입니다.

```
나 > 내일 3시에 약 먹으라고 알려줘                      ← 알림: 그 시각에 문구를 읽어줌
나 > 매주 월요일 아침에 AI 소식 조사해서 문서로 만들어놔  ← 지시: 루시가 실제로 그 일을 함
```

**지시**는 그 시각에 루시가 도구를 써서 일을 하고(조사·문서 만들기), 결과를 `memory/tasks/`에 적은 뒤
"다 했어요" 한 줄만 소리로 알려줍니다(답 전체를 읽으면 몇 분이 걸리니까).

⚠️ 사람이 화면 앞에 없을 때 도는 일이라 규칙을 미리 정해 뒀습니다(`tools.UNATTENDED`):
**파일·문서 쓰기는 허용**(지시할 때 이미 허락한 일이므로), **코드·명령 실행은 거부**.
이 구분이 없으면 둘 중 하나가 됩니다 — 전부 막아서 예약 지시가 무용지물이 되거나,
전부 열어서 배경에서 임의 코드가 도는 물건이 되거나.

지금 바로 시켜보려면: `python notify.py --task "오늘 날짜 알려줘"`

## 아침 브리핑 · 지식 자동 동기화

작업 스케줄러가 1분마다 부르는 알림 일꾼(`notify.py`)이, 예약을 보는 김에 **오늘 아직 안 한 일**도 합니다.

- **아침 브리핑** (`daily.briefing.at`, 기본 08:00 · 기본 꺼짐) — 오늘 날짜·일정, 어제 나눈 이야기,
  관심사 소식을 루시가 **생각해서** 말로 들려줍니다. `/브리핑`으로 지금 받아볼 수도 있습니다.
  사실은 파이썬이 모아 넘기고 모델은 말로 엮기만 합니다 — 배경에서 도는 일은 단순할수록 오래 삽니다.
- **지식 창고 동기화** (`daily.knowledge_sync.at`, 기본 05:00) — 클로드가 갱신한 노트를 가져오고
  바뀐 조각만 미리 임베딩합니다. 안 하면 루시가 옛 정보를 말합니다(`/지식갱신`을 눌러야만 최신이 됐음).
- **늦게라도 한 번**: 컴퓨터가 꺼져 있었으면 켠 뒤에 합니다. 단 너무 늦으면 건너뜁니다
  (밤 11시에 "좋은 아침입니다"라고 하지 않게 — `catch_up_hours`).

## 실수 노트 (경험 축적)

사용자가 **"아니 그거 틀렸어"**라고 지적하면, 그 일에서 교훈 한 줄을 뽑아 `memory/lessons.md`에 적습니다.
다음에 **비슷한 질문**이 오면 그 교훈을 먼저 읽고 답합니다.

```
나 > 샐러드팜 생물이 몇 종이야?
루시 > 41종입니다.
나 > 아니 틀렸어. 세션35에서 32종으로 줄였잖아.
루시 > ...
       [실수 노트] 적었습니다 — 샐러드팜 생물 종 수를 41종이라 답했으나 32종임.
                   수치는 기억에 의존하지 말고 노트를 확인할 것

(다음에)
나 > 샐러드팜 생물 종류가 몇 개였지?
       [실수 노트] 임베딩(bge-m3) · 1/1개 (최고 0.72)     ← 교훈을 먼저 읽고 답합니다
```

- `/교훈` — 노트를 봅니다. `/교훈 삭제 <말>` — 지웁니다. 손으로 적어 넣어도 됩니다.
- 지적이 비서의 잘못이 아니거나 일회성이면 **적지 않습니다**(모델이 판단). 빈 노트가 오염된 노트보다 낫습니다.
- 같은 교훈은 임베딩 0.90 이상이면 중복으로 걸러집니다.
- **왜 `notes.md`와 통을 나누는가**: `notes.md`는 *사실*("사용자는 홍차를 좋아함"), 실수 노트는 *행동 지침*입니다.
  섞으면 검색 공간이 흐려지고, 매 질문에 딸려가는 개인 사실과 달리 교훈은 '비슷한 실수 상황'에서만 나와야 합니다.

## 컨텍스트 자동 압축

대화가 길어지면 토큰 한도를 넘겨 요청 자체가 거절됩니다(무료 Cerebras는 **컨텍스트 8192**라 가장 먼저 죽음).
글자수가 `context.max_chars`를 넘으면 오래된 턴을 모델이 요약해 한 덩어리로 접고, 최근 몇 턴만 원문으로 둡니다.

```
    [압축] 대화가 길어져 오래된 부분을 요약으로 접었습니다
```

- 자르는 위치는 반드시 **사용자 발언 경계**입니다. 아무 데서나 자르면 도구 결과(`tool`)가 자기를 부른
  `tool_calls`와 짝이 어긋나 400이 납니다.
- 요약에 실패해도 대화는 계속됩니다(오래된 원문을 버리되, 버렸다는 사실은 남깁니다).
- 이미지가 실린 턴은 `[이미지]`로 세고 요약합니다 — base64를 글자수로 세면 "대화가 길다"고 오판하고,
  요약 프롬프트에 base64를 쏟아붓게 됩니다.

## 교차검증: `/검증 <질문>`

**서로 다른 두 두뇌에게 따로 묻고 답을 대조**합니다. 일치하면 하나로 정리하고, 엇갈리면 그 사실을
밝힙니다. 중요한 질문에 쓰세요. 느리고 무료 한도를 두 배로 쓰기 때문에 붙일 때만 작동합니다.

> 모델을 **합치는 것**(mergekit 같은 가중치 병합)은 부모보다 똑똑해지지 않습니다. 반면 각자 답하게
> 한 뒤 대조하는 건 실제로 오류를 잡아냅니다. "여러 AI를 합쳐 똑똑하게"의 유일하게 작동하는 버전입니다.

프롬프트에서 **`음성`** 또는 **`/v`** 입력 → 말하고 → 엔터. 받아쓴 내용이 질문으로 들어갑니다.

- 마이크가 없으면 안내만 뜨고 비서는 그대로 작동합니다

## 대화 기억 + 종료 시 자동 요약

- 모든 대화는 `memory/history/날짜.md` 에 그대로 남습니다
- **`exit` 할 때** 비서가 이번 대화에서 "앞으로도 알아야 할 사실"만 골라 `notes.md` 에 저장합니다
  (일회성 질답은 걸러내고, 이미 있는 기억과 비슷하면 중복 저장하지 않음 — 임베딩 유사도 0.90 기준)
- 저장된 기억은 다음 실행부터 관련 질문에 자동으로 딸려옵니다

## 기억 정리 (주 1회 자동 + `/기억정리`)

기억은 들어올 때만 걸러지므로 시간이 지나면 같은 주제가 여러 줄로 흩어지고 지난 일정이 남습니다.
그래서 **일주일에 한 번 새벽에**(기본 05:20, `config.json`의 `daily.consolidate`) 모델에게 기억
목록을 보여주고 정리합니다 — 같은 주제 병합 · 모순은 나중 날짜 우선 · 지난 일정 삭제.
`notes.md`와 `lessons.md`(실수 노트) 둘 다 다룹니다.

- 모델은 "몇 번과 몇 번을 합쳐라" 같은 **작업 목록만 제안**하고 검증·적용은 코드가 합니다
  (통째로 다시 쓰게 하면 멀쩡한 기억이 조용히 빠져도 알 수 없기 때문)
- 지목되지 않은 기억은 글자 하나 안 바뀌고, 제안이 절반을 넘게 건드리면 통째로 버립니다
- 적용 전 원본이 `memory/backups/`에 남아 언제든 되돌릴 수 있습니다
- **`/기억정리`** — 지금 훑어서 제안을 보여주고, y라고 해야 적용합니다

## 스스로 배우기 (`study.py`)

지금까지 루시가 배우는 길은 셋 다 수동적이었습니다 — 사용자의 지적, 검사관의 퇴짜,
종료 시 요약. 이제 **아무도 시키지 않아도** 매일 새벽(기본 05:30) 두 가지를 합니다.

- **복습(자기 반성)** — 어제 대화를 되읽고, 지적받지 않았어도 아쉬웠던 순간
  (같은 걸 두 번 묻게 함, 의도 오해, 추측으로 답함)에서 교훈을 뽑아 실수 노트에
  적습니다. 하루 최대 2개, 이미 아는 교훈과 겹치면 안 적습니다. **없으면 없는 게 정답.**
- **자가 공부** — 어제 얕게 답했던 주제 하나를 골라 스스로 깊이 조사하고(research)
  `knowledge/selfstudy_*.md` 노트로 정리합니다. 같은 주제를 다시 물으면 검색부터
  하는 대신 공부해 둔 노트로 답합니다. 노트에는 '자가 학습·검증 안 됨'을 밝혀 두고,
  조사가 빈손이면 노트를 만들지 않습니다(자료 없는 노트는 지어낸 노트).

지금 바로 하려면: **`/복습`** (오늘/최근 대화 되돌아보기), **`/공부 <주제>`**
(주제를 안 주면 최근 대화에서 스스로 고릅니다). 설정은 `config.json`의 `daily.study`.

## 자가 진단·수리 (`doctor.py`)

루시는 멈추지 않으려고 문제를 조용히 삼킵니다 — 목소리 서버가 꺼지면 말없이 구글
목소리로, Ollama가 꺼지면 말없이 단어겹침 검색으로 내려갑니다. 겉으로는 고장인지
폴백인지 구분이 안 되므로, 스스로 점검하고 **켜서 고칠 수 있는 것은 그 자리에서 켭니다**.

점검 대상: 로컬 목소리 서버(멜로) · Ollama(기억·지식 검색) · 알림 스케줄러 · 구글 연동.

| 언제 | 어떻게 |
|---|---|
| 루시를 켤 때 | 문제가 있을 때만 한 줄씩 말하고 고침(정상이면 조용) |
| **`/점검`** | 전부 보여줌(정상 포함) |
| 대화 중 "목소리가 왜 이래?" | 루시가 **스스로 `self_check` 도구를 불러** 진단·수리하고 설명 |
| 매일 새벽(05:10) | 알림 일꾼이 제 몸을 살핌 — 재부팅 뒤 서버들이 꺼진 채 방치되지 않게 |

수리는 전부 '켜는 것'뿐입니다 — 지우거나 바꾸는 수리는 사람과 상의할 일이라 하지 않습니다.

## 클로드와의 기록 물려받기

루시는 **클로드(개발 AI)가 세션마다 정리해둔 프로젝트 노트**를 읽을 수 있습니다.
샐러드팜 게임, 알약 협동 게임 기획, 식사 AI 학습, 빌드·아트 규칙 같은 작업 내역입니다.

| | 무엇 | 어떻게 |
|---|---|---|
| **`knowledge/`** | 정제된 노트 62개 (330KB) | `search_knowledge` 도구가 임베딩으로 찾아 읽음 |
| **원본 대화** | 54세션 253MB (`.jsonl`) | `search_history` 도구가 키워드로 훑어 해당 대목만 꺼냄 |

> "내 샐러드팜에서 생명체 진화 조건이 뭐였지?" → 루시가 노트를 찾아 **기본 → 성장(5레벨) →
> 진화(10레벨), 진화 시 골드 2배**라고 답합니다.

**원본 253MB를 기억에 붓지 않은 이유**: 날것에는 도구 로그·파일 전문·실패한 시도가 다 들어 있어서,
노이즈에 파묻혀 정작 중요한 걸 못 찾게 됩니다. 그래서 **요약은 항상 곁에 두고(knowledge), 상세는
필요할 때만 뒤집니다(history)**. 개인 사실 기억(`notes.md`)과도 통을 나눴습니다 — "홍차를 좋아함"과
"premium9 아트 리디자인"이 한 통에 있으면 둘 다 흐려집니다.

클로드가 노트를 새로 쓰면 **`/지식갱신`** 으로 다시 가져옵니다. 첫 검색 때 임베딩 인덱스를 만드느라
3~4분 걸리고, 그 뒤로는 2~3초입니다.

## 두뇌 벤치: `/벤치`

**루시가 자기 두뇌들을 직접 시험해서 순위를 다시 매기고 `config.json`을 고쳐 씁니다.**
무료 모델판은 계속 바뀝니다 — 어제 빠르던 게 오늘 한도에 걸리고, 서비스가 프로젝트를 막아버리기도
합니다(실제로 Gemini가 403으로 차단됐습니다). 그때마다 손으로 순서를 고치는 대신 루시가 재게 합니다.

재는 것은 "똑똑함"이 아니라 **이 비서가 실제로 하는 일**입니다.

1. 사실 질문에 검색 도구를 써서 정답을 내는가 (도구 호출 + 환각 방지)
2. 도구 두 개를 엮어 쓸 수 있는가 (다단계 실행)
3. 계산을 틀리지 않는가 (추론)

결과대로 **1등이 주력(맨 앞), 만점 중 가장 느린 모델이 `deep`(어려운 질문 담당)**이 됩니다.
원본은 `config.json.bak`으로 백업하고, 적용 전에 물어봅니다.

> **채점의 함정 두 가지** (실제로 겪고 고친 것)
> - **한도 초과는 오답이 아닙니다.** 429를 맞은 과제는 '측정 불가'로 빼고 분모에서 제외합니다.
>   안 그러면 멀쩡한 모델이 0점으로 꼴찌가 됩니다.
> - **정답률만 보면 안 됩니다.** 한 문제만 풀고 한도에 걸린 모델(1/1 = 100%)이 세 문제를 다 맞힌
>   모델(3/3)을 이겨버립니다. 그래서 **맞힌 개수 → 정답률 → 속도** 순으로 봅니다.
>
> 과제 사이에 4초씩 쉽니다. 쉬지 않고 연타하면 **벤치가 스스로 분당 한도를 터뜨려** 멀쩡한 모델을
> '한도 초과'로 찍습니다. 로컬 모델은 과제당 5분이 넘고 어차피 항상 맨 아래라 건너뜁니다.

## 난이도 라우팅 + 한도 초과 기억하기

- **짧고 단순한 질문** → 빠른 주력(Groq, 2초)으로 즉답
- **길거나 어려운 질문**("왜", "설계", "비교", "코드"…) → `deep: true`인 두뇌부터 (느리지만 정확)
- 어느 쪽이든 실패하면 폴백이 그대로 작동하므로 답을 못 받는 일은 없습니다

**한도 초과(429)를 맞은 모델은 30분간 건너뜁니다**(`quota_cooldown_min`). 이게 없으면 무료 한도가
마른 모델을 질문마다 한 번씩 찔러보고 실패한 뒤에야 다음으로 내려가서, 모든 답이 그만큼 느려집니다.

> 세션41 벤치(도구 호출·정답·속도를 실제 에이전트 루프로 측정) 결과 주력을 Groq `qwen3.6-27b`로
> 바꿨습니다. Gemini 무료는 **일일 한도가 금방 말라서**(`gemini-3.5-flash`·`3.1-pro` 모두 429)
> 주력에 두면 매번 헛발질을 합니다. 모델마다 한도가 따로라 `gemini-3-flash-preview`는 살아 있어서
> '깊은 생각용'으로 남겼습니다. ⚠️`gpt-oss-120b`는 분당 8000토큰 제한이라 도구 명세를 실으면
> 요청 자체가 413으로 거부됩니다 — 쓰지 마세요.

`config.json`의 `routing.enabled`로 끌 수 있습니다.

## 기억 검색 (임베딩 / RAG)

기억을 전부 프롬프트에 밀어넣지 않고, **질문과 의미가 가까운 것만** 골라 넣습니다.
`bge-m3` 임베딩 모델(로컬)이 문장을 벡터로 바꿔서 비교하기 때문에, 단어가 안 겹쳐도 찾아냅니다.

- "**주말**에 뭐 하지?" → "매주 **토요일** 등산" 을 찾아냄
- "앱 **서명**할 때 뭐 필요해?" → "**키스토어** 위치" 를 찾아냄
- 관련 기억이 없으면 아무것도 넣지 않음 (헛소리 방지)

기억이 8개 이하일 땐 검색 없이 전부 넣습니다(그게 더 정확함). Ollama가 꺼져 있으면
단어 겹침 방식으로 자동 강등돼서, **어떤 경우에도 비서가 멈추지 않습니다.**

**검색어 재정의** — 1등 유사도가 `memory_confident_score`(0.60)에 못 미치면, 즉 **검색이 자신 없으면**
모델에게 검색어를 다시 뽑게 해서 한 번 더 찾고 결과를 합칩니다.

> "앱 서명할 때 그거 필요하지 않았나?" → 1차 검색은 엉뚱한 걸 가져왔습니다(0.48).
> 재정의("앱 서명 인증서, 키 스토어, 서명용 개인키")로 다시 찾아 **키스토어 위치**를 건져냈습니다.
>
> 실패는 '빈손'이 아니라 **'엉뚱한 걸 낮은 점수로 가져오는 것'**으로 나타납니다. 그래서 빈손일 때만
> 재검색하면 못 잡습니다. 확신이 있을 땐 부르지 않으므로 무료 한도는 거의 그대로입니다.

기준값은 `config.json`의 `memory_top_k`, `memory_min_score`(0.45), `memory_relative_ratio`(0.85),
`memory_confident_score`(0.60).

## 웹 검색

HTML을 긁는 방식(DuckDuckGo 등)은 **전부 봇 차단으로 막혔습니다.** 그래서 백엔드를 순서대로 시도합니다:

1. **Tavily** — 무료 키(**카드 불필요**, 월 1000회). https://www.tavily.com 에서 발급 → `keys/tavily.txt`
2. **위키백과** — 키 불필요. **항상 작동하는 바닥.** 단, 백과사전이라 최신·시사 정보엔 약함

키를 안 넣어도 위키백과로 굴러가고, Tavily 키를 넣으면 진짜 웹 검색이 열립니다.

> ⚠️ **Brave Search API는 일부러 뺐습니다.** 2026년 초 무료 티어가 폐지돼 카드 등록이 필수이고,
> 월 $5 크레딧을 넘으면 **상한 없이 자동 청구**됩니다. 코드(`_search_brave`)는 `tools.py`에 남아
> 있으니, 감수하고 쓰려면 `config.json`의 `search_backends`에 다시 넣으면 됩니다.

## 서비스가 종료되면?

`config.json`의 `models` 목록에서 **그 블록만 지우면 끝.** 나머지는 그대로 작동합니다.

새 공급자를 넣을 때는 OpenAI 호환 주소만 있으면 됩니다:

```json
{ "label": "새 공급자", "base_url": "https://.../v1", "model": "모델이름", "key_file": "keys/새키.txt" }
```

인터넷이 아예 없어도 로컬 Ollama만 있으면 작동합니다.
