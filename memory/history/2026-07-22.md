### 1️⃣ 재귀(recursion)란?  
- **정의**: 함수가 자신의 몸체 안에서 스스로를 호출하는 기법.  
- **동작 원리** (출처 [1])  
  1. 함수 호출 시 **새로운 프레임**이 호출 스택에 쌓인다.  
  2. 각 호출은 **인자·지역 변수·리턴 주소**를 별도로 보관한다.  
  3. **기저 조건(base case)**에 도달하면 재귀 호출을 멈추고 스택을 역순으로 풀어 반환한다.  
- **특징**  
  - 호출이 늘어날수록 스택이 깊어져 메모리 사용량이 증가한다.  
  - 함수 호출 오버헤드가 존재하므로 일반적으로 순수 루프보다 느릴 수 있다.  
  - 깊이가 너무 커지면 스택 오버플로(재귀 깊이 제한)에 도달할 수 있다(스택 프레임 증가에 따른 자연스러운 결과).  

### 2️⃣ 반복문(iteration)란?  
- **정의**: 동일한 동작을 일정 횟수 혹은 조건이 만족될 때까지 반복 실행하는 제어 구조. 파이썬에서는 주로 `for`와 `while` 문을 사용한다.  
- **동작 원리** (출처 [1])  
  - `for`는 **이터레이터**(시퀀스, range, generator 등)를 받아 **각 요소를 차례대로** 꺼내면서 블록을 실행한다.  
  - `while`은 **조건식이 True**인 동안 블록을 계속 실행한다; 루프 내부에서 조건을 변경해 종료시킨다.  
  - 반복문은 **루프 카운터·조건만 관리**하고, 함수 호출 스택을 쌓지 않는다 → **메모리 사용이 일정**하고 **오버헤드가 적다**.  
- **특징** (출처 [1])  
  - `break` 구문을 통해 루프 내部에서 조기 종료가 가능하다.  
  - 중첩 루프(중첩된 반복문)를 형성할 수 있다.  
  - 숫자 기반 루프는 BASIC, Pascal, 포트란 등에서 보이는 형태와 유사하게 동작한다(출처 [1] 예시).  

### 3️⃣ 재귀 vs 반복문의 핵심 차이점 (출처 [1] 및 [2] 종합)  

| 항목 | 재귀 | 반복문 |
|------|------|--------|
| **구현 방식** | 함수가 자기 자신을 호출 | 한 블록을 여러 번 실행 (`for`/`while`) |
| **스택·메모리** | 호출마다 새로운 스택 프레임 → 메모리 사용량 ↑, 깊이 제한 존재 | 스택 변동 없음 → 메모리 사용량 일정 |
| **성능** | 함수 호출 오버헤드 + 스택 관리 → 일반적으로 느림 | 순수 루프 실행 → 빠름 (특히 `for`가 C‑level 반복자를 활용) |
| **가독성·표현력** | 트리·분할‑정복·재귀적 정의가 직관적 (예: 이진 트리 탐색) | 순차적·선형 흐름이 명확, 복잡한 재귀 로직을 루프로 바꾸면 코드가 장황해질 수 있음 |
| **제한** | 재귀 깊이가 깊어지면 스택 오버플로 위험 | 조건에 따라 종료되며 별도 깊이 제한 없음 |
| **최적화** | 함수형 언어(예: 스킴)는 꼬리 재귀 최적화(tail‑call optimization)를 수행하여 반복과 동등한 효율 달성 가능 (출처 [2]) | 파이썬의 `for`는 내부적으로 최적화된 반복자를 사용 |

### 4️⃣ 재귀를 사용하는 것이 좋은 경우  
- **트리·그래프 탐색** (예: 이진 트리 전위/중위/후위 순회) – 재귀가 트리 구조와 자연스럽게 맞아떨어져 코드가 간결해짐.  
- **분할‑정복 알고리즘** (예: 퀵 정렬, 머지 정렬, 이진 탐색) – 문제를 “절반씩 나누어 재귀적으로 해결”하는 접근이 직관적.  
- **재귀적 정의가 명확한 수학 함수** (예: 팩터리얼, 피보나치) – 정의 자체가 재귀이므로 구현이 가장 직관적.  
- **백트래킹·조합 탐색** (예: N‑Queens, 퍼즐 해결) – 현재 상태·다음 상태를 재귀 호출 스택에 자연스럽게 쌓아 탐색.  
- **재귀적 데이터 구조 변환** (예: 중첩 리스트를 평탄화) – 중첩 깊이에 따라 같은 로직을 재귀적으로 적용.  
- **조건**: 입력 규모가 작거나 재귀 깊이가 제한 안에 들어갈 때, 가독성을 우선시하고 성능이 제약이 아닌 경우에 적합.  

### 5️⃣ 반복문을 사용하는 것이 좋은 경우  
- **대용량 순회** (예: 파일 라인 읽기, 리스트/배열 순회) – 메모리·시간 효율이 높으며 스택 오버플로 위험이 없음.  
- **단순 누적·계산** (예: 합계, 평균, 통계) – `for`·`while`이 가장 빠르고 직관적.  
- **조건 기반 반복** (예: `while` 루프를 통한 이벤트 대기) – 명시적 종료 조건 관리가 쉬움.  
- **배열·시퀀스 변환** (list comprehension, `map`, `filter`) – 파이썬 내장 반복 구조가 최적화돼 빠름.  
- **성능‑critical 루프** (예: 수치 연산, 게임 로직) – 재귀 호출 오버헤드 없이 순수 C‑level 반복 수행.  
- **재귀 제한을 우회** (재귀 깊이가 1 000 초과될 경우) – 스택 사용을 없애고 동일 로직을 반복문으로 재작성.  
- **반복 횟수가 명확히 알려진 경우** (`range(N)`) – `for i in range(N):` 은 가장 효율적인 카운터 루프.  

### 6️⃣ 결론  
- **재귀**는 자기 호출을 통해 문제를 작은 동일한 하위 문제로 분해하는 방식으로, 트리·분할·정복 등 재귀적 정의가 자연스러운 문제에 적합하다. 다만 스택 프레임이 쌓여 메모리 사용이増加하고 깊이가 커지면 오버플로 위험이 있다(출처 [1]의 스택 프레임 설명에 기반).  
- **반복문**은 루프 카운터·조건만을 관리하며 스택을 사용하지 않으므로 메모리 사용이 일정하고 오버헤드가 적다(출처 [1]). 대용량 데이터 처리나 성능이 중요한 상황에 적합하다.  
- 실전에서는 **가독성 vs 성능·안정성**을 기준으로 선택한다:  
  - 가독성을 중시하고 입력 규모가 작거나 재귀 깊이가 제한 안에 들면 → 재귀.  
  - 성능·안정성을 최우선으로 하고 입력이 크거나 재귀 깊이가 깊을 경우 → 반복문(또는 명시적 스택·큐 활용).
