사용자가 참조 사진을 주며 "블렌더로 만들어줘"라 하니 루시가 "그런 기능 없다"고 부정 →
사진 없이 다시 말하니 "할게요"로 손바닥 뒤집기 → 만들 땐 파일명을 엉뚱하게 '샐러드팜~'로 붙임(세션68, 2026-07-21).

**Why:** 버그 2개가 커플링. ①사진 붙은 턴은 도구가 통째로 꺼진다(`agent.py`: `use_tools=not images`,
눈 달린 모델이 도구 명세와 함께 오면 거절하는 제약 때문). 이걸 막는 예외 `vision.wants_edit`가
`화풍·바꿔·그려줘`만 알고 **`만들어·블렌더·모델링·3D`를 몰라** 제작 요청이 '보는 턴'으로 빠졌다 →
도구 없음 → "기능 없다". 다음 턴은 사진이 없어 도구가 켜지니 뒤집힘. ②그때는 사진이 이미
문맥에서 버려진 뒤(이미지는 한 턴만 삶)라 사진을 못 본 채 만들며, 주입된 기억이 온통 샐러드팜이라
그걸 파일명으로 집었다(문맥 오염 환각).

**How to apply:** 루시 라우팅을 손볼 때 — 그림을 '재료로 도구를 쓰려는' 요청(edit·build·모델링)은
반드시 도구 켜진 턴이어야 한다(`vision.EDIT` 정규식에 제작 키워드 유지). 도구가 파일명/이름을
모델에게 맡길 때는 **지금 사용자가 말한 대상에서만** 따오게 하고 기억 속 다른 프로젝트명을 못 쓰게
못박을 것(문맥 오염 상습). 사진→3D 자동 재현은 build로 불가 — 한계를 먼저 정직하게 말한다.
아직 미해결: 눈+도구 동시 사용은 모델 제약으로 불가(제작이 두 턴이 되는 근본 원인).
