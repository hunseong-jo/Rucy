# 유니티 도구 레이어 규격 + 세션72 재작업 (2026-07-23)

친구(유니티 개발자)가 전한 규격. **이게 앞으로 플레이어 애니의 계약서다.**

## ★ 대원칙
유니티는 `Armed`/`Swing`/`Shoot`/`Use` **4개 전신 레이어**를 로코모션 위에 얹고,
상태 전환은 **엔진이 0.25초 크로스페이드**로 처리한다.
=> **도구 상태 클립은 "이미 그 자세인 채로의 순환"이어야 한다. 팔을 올리고 내리는 *동작*을 클립에 넣지 말 것.**
넣으면 마우스 꾹 누를 때 팔이 무한 왕복한다. **예외는 Swing 하나뿐**(휘두르기는 동작 자체가 콘텐츠 → 1회성).

## 고정 규격
- 프레임 수는 베이스와 **반드시 동일**: Idle 90(루프) / Walk 25(루프) / Run 17(루프) / Jump 45(논루프).
  다르면 발이 미끄러진다. Walk/Run 변형은 **같은 프레임에 같은 발 접지**(상체만 바꾼 복제본이 이상적).
- Swing만 예외: **10프레임(0.30초) 논루프**. 근접공격 최소 간격 0.5초라 0.32초 넘기면 스윙끼리 겹침.
  1프레임 = 마지막 프레임 = **대응 Armed 클립의 자세**(안 그러면 레이어 꺼질 때 튐).
- 아마추어 루트 `PlayerRig` / 손 본 `Forearm_R`(도구 부착점) 이름 유지, 스케일 1로 export, Generic 리그, 제자리(루트모션 없음).
- 경로 `Assets/TOOLSMesh/Player/`, 파일명 `player@<클립>.fbx`, **블렌더 액션 이름도 클립명과 동일**.
- 유니티 임포트 설정(리그·아바타·루프 플래그)은 친구 쪽에서 자동 처리 — 건드릴 필요 없음.

## 세션72 재작업 결과 (12클립, 스크립트 `player_리깅\build_layerfix.py`)
- **유지 루프화 8종**: `{Idle,Walk,Run,Jump}{Use,Shoot}`. 올림/내림 삭제, Q_AIM 정점 자세 고정 + 미세 호흡만.
  ⭐**의뢰서엔 Idle 2개만 고치라 했지만, 재보니 Walk/Run/Jump 6개도 어깨 73.4°·팔꿈치 55°로 왕복 중이라 전부 수정했다**(작업③ "확인만"이 실제론 수정이었음).
- **1회성화 4종**: `*Swing` 90/25/17/45f → 전부 10f. 배치 = 1 준비 → 4 치켜듦 → 7 내리침(t^1.8 가속) → 8 팔로스루 → 10 준비 복귀.
- **손 안 댐**: `*Armed` 4종(이미 유지 루프 맞음, 어깨 폭 0.1~6.4°), 베이스 4종, Stun/Downed.

⭐**흔들림은 반드시 sin(2πp)·sin(4πp) 계열로** — p=0,1에서 정확히 0이라 1프레임=마지막프레임이 공짜로 성립. cos 쓰면 이음매가 튄다.

## ⚠️ 미해결 — Swing 하체 위상
스윙만 10f라 로코모션과 프레임 수가 다르다. 하체 처리:
- Walk/Run = 한 사이클을 10f로 리샘플(스트라이드 보존, 사이클이라 1f=10f 성립)
- Idle/Jump = 대응 Armed f1 자세로 고정(보존할 사이클 없음)
🚨**JumpSwing은 "지상 자세" 고정이라 점프 정점에서 스윙하면 하체가 228mm(키의 12%) 내려앉는다.**
Jump의 상승 아크가 Hips 본 이동(0→0.22)에 실려 있어 10f 클립으론 위상을 맞출 수가 없음.
Walk/RunSwing도 다리가 0.3초에 2.5배 속도로 한 스트라이드를 돈다.

✅**해법 납품(사용자 승인 2026-07-23)**: Swing 레이어용 Avatar Mask 2종을 만들어 `player_유니티용\`에 넣음.
- `Swing_ArmOnly.mask` (권장) = `Arm_R`+`Forearm_R`만 켬. 휘두르는 건 오른팔뿐이라 충분하고 왼팔·상체 위상 어긋남까지 없앰.
- `Swing_UpperBody.mask` = Spine·Head·양팔. 왼팔 반동을 레이어에 맡기고 싶을 때.
🚨⭐**Root와 Hips는 반드시 꺼야 한다** — 켜면 스윙 클립의 고정된 Hips가 점프 상승 아크를 덮어써서 문제가 그대로 돌아옴. (내가 처음 안내문에 "Root/Hips/Spine…을 켜라"고 잘못 적었다가 마스크 만들면서 발견해 정정함.)
⚠️유니티 실재생 테스트는 못 함(프로젝트가 친구 쪽). 경로 17개가 FBX 실계층과 1:1인 것만 대조 확인.
⚠️Inspector에서 부모 항목을 껐다 켜면 자식까지 따라 바뀜 — 지정만 하고 열지 말라고 안내함.
마스크를 안 쓴다면 JumpSwing을 "공중 자세" 고정으로 재납품(이번엔 이륙/착지가 어긋남).

⭐**본 계층**(마스크 경로): `PlayerRig/Root/Hips/{Spine/{Head,Arm_L/Forearm_L,Arm_R/Forearm_R}, Leg_L/Foot_L/Shin_L, Leg_R/Foot_R/Shin_R}`, 메시는 `PlayerRig/PlayerMesh`.
⚠️다리 본 이름이 한 칸씩 밀려 있다 — **`Foot`이 중간(정강이), `Shin`이 끝(발)**. 그래서 로코모션이 `Leg_*`엔 키가 없고 `Foot_*`/`Shin_*`만 움직인다.

## 검증 방법(재사용)
1. blend에서 액션별 `Arm_R.X` 각도 폭 + f1/flast 전채널 maxdiff
2. **납품 FBX 되읽기** — ⚠️`import_scene.fbx(ignore_leaf_bones=True)`면 본이 14→10으로 줄어 `Forearm_R`이 사라진 것처럼 보인다. **반드시 False로.**
3. ⚠️팔 유지 여부를 **월드좌표로 재면 안 됨** — Jump는 Root 회전 키가 있어서 몸 전체가 돌면 상대벡터도 돌아 95mm 오차가 뜬다(팔은 멀쩡한데). **Hips 본 좌표계 국소값으로 잴 것**(그러면 6.5mm).
4. 구버전 정점 프레임 vs 신버전 f1 렌더 대조(픽셀 변화율) — 유지 자세가 진짜 그 정점인지 확인
