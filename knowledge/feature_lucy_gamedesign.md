## ⚠️ 저자 환각 — 파일명에 저자를 넣어야 한다 (실제로 겪음)
루시가 보상 설계를 잘 설명해놓고 **출처를 "Graham Gaylor, Jesse Joudrey"라고 지어냄**(실제 저자는 이상균). 슬라이드 본문에 사례로 나온 인명을 저자로 착각한 것.

**원인**: `knowledge.py`의 `_chunks_of()`는 조각의 이름표로 **파일명(stem)만** 붙인다. 문서 머리에 적은 "저자·출처"는 **첫 조각에만** 들어가므로, 중간 슬라이드가 검색되면 저자 정보가 없다 → 모델이 본문 인명을 주워 씀.

**해결**: 파일명 끝에 저자를 박는다 → 모든 조각의 이름표에 저자가 따라다님.
`gamedesign_기획튜토리얼_이상균.md` / `_기획서작성법_이상균` / `_기획서작성법_GDC2008` / `_모바일기획실습_Sunnyrider` / `_밸런싱개론_구승모` / `_밸런싱핸드북_클로드`
+ `search_knowledge` 도구 설명에 "저자는 파일명 끝에 있다. 본문 인명을 저자로 착각 말 것. 확인 안 되면 지어내지 말 것" 명시.
**교재를 추가로 넣을 때는 파일명에 저자를 반드시 넣을 것.**
검증 후: "(구승모, gamedesign_밸런싱개론; p27-30)"처럼 저자·파일·슬라이드번호까지 정확히 인용함.

## 함정
- **stdin 파이프로 루시를 테스트하면 한글이 깨져 UnicodeEncodeError**(surrogates not allowed). 파이썬이 파이프를 cp949로 디코딩함. → 서브프로세스에 `PYTHONIOENCODING=utf-8` 줄 것. 루시 자체 버그 아님(터미널 직접 입력은 정상).
- 재인덱싱은 **새 조각만** 임베딩(해시 캐시) — 교재 5종 추가 = 748벡터, 9.8MB, 약 9분. 한 줄 고치면 5초. **파일명을 바꾸면 그 파일의 전 조각이 재임베딩**(이름표가 텍스트에 포함되므로) — 178조각 4분.
- **동시 세션 주의**: 이 세션과 다른 Claude 창이 동시에 my-agent를 손봤음(그쪽=마케팅 PDF 학습 → SD WebUI). `index.json`은 통째로 읽고 쓰므로 **양쪽에서 재인덱싱 동시 실행 금지**(한쪽이 통째로 날아감). config.json·tools.py도 충돌 지점.
