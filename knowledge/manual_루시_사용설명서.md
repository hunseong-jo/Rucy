# 루시 사용설명서

(2026-07-26 기준, 도구 77종 · 세션77까지 반영)

이 문서는 루시의 공식 사용설명서다. 사용자도 읽고, 루시 자신도 지식 창고(search_knowledge)로 찾아본다.
루시가 "너 뭐 할 수 있어?", "그 명령어 뭐였지?", "이 기능 어떻게 써?" 같은 질문을 받으면 이 문서를 근거로 답한다. 추측으로 답하지 않는다.

## 루시를 켜는 법

- `start.bat` — 터미널 루시. 멜로(부드러운 목소리) 서버도 같이 켜진다.
- **웹 화면과 목소리 서버는 로그온하면 자동으로 켜진다**(작업 스케줄러 "Lucy 웹"·"Lucy 목소리") — 재부팅해도 손댈 것 없음. 수동으로 켜려면 `start_web.bat`·`start_voice.bat`.
- 웹 접속: 같은 와이파이에서 `http://<PC IP>:8765`, 밖에서는 폰의 Tailscale을 켜고 `http://100.74.78.102:8765`. 첫 접속은 PIN 입력(PC의 `keys/web_pin.txt`), 한 번 넣으면 90일 기억.
- 웹 화면에서 되는 것: 대화(터미널과 같은 루시) · **사진·녹음·문서 올리기**(📷 버튼 — PDF·워드·엑셀·PPT·한글(hwpx)을 올리고 "요약해줘"라고 하면 됨) · **🎤 음성 대화**(누르고 말하고 다시 누르면 받아쓴 질문과 답이 옴, 답은 소리로도 나옴) · 읽어주기(폰 스피커) · **📜 지난 대화 보기**(PC에서 나눈 이야기를 날짜별로 이어봄) · **파일 내려받기**("그 기획서 폰으로 줘"라고 하면 답 밑에 내려받기 링크가 달림 — 바탕화면·문서·다운로드 폴더 안의 파일만) · **답이 예쁘게 보임**(표·코드·글머리표·굵게를 마크다운으로 렌더 — 2026-07-15).
- **시간이 걸리는 일(영상 인코딩 등)을 웹에서 시키면** 20초쯤 뒤 "계속하고 있어요"라고 먼저 답이 오고, 끝나면 그 말풍선에 진짜 답이 달린다. 기다리는 동안 다른 질문을 해도 된다(화면이 몇 분씩 멈춰 있던 예전 동작이 고쳐진 것).
- ⚠️🎤 마이크는 브라우저 규칙상 **https(또는 PC의 localhost)에서만** 열린다. 폰에서 쓰려면 Tailscale의 https 주소가 필요: 관리자 페이지에서 HTTPS를 한 번 켜고(`tailscale serve --bg 8765` 실행 시 안내 링크가 뜸) `tailscale serve --bg 8765`를 실행하면 `https://<pc이름>.<테일넷>.ts.net` 주소가 생긴다. http 주소에서는 🎤가 안내 문구만 띄운다(대신 📷로 녹음 파일을 올리면 됨).
- `python agent.py --local` — 프라이버시 모드. 외부로 아무것도 안 보내고 로컬 두뇌·로컬 목소리만 쓴다.
- 알림·새벽 일과는 루시 창이 꺼져 있어도 돈다(윈도우 작업 스케줄러 "Lucy 알림"이 1분마다 확인). 단, PC가 켜져 있어야 한다.
- **웹 루시 PWA (스마트폰 앱 환경)**: 스마트폰 브라우저 메뉴에서 '홈 화면에 추가' 또는 '앱 설치'를 누르면 스마트폰 전용 앱처럼 홈 화면 아이콘으로 독립 실행 가능 (`manifest.json` 및 `sw.js` 백그라운드 지원).
- **폰 Termux:Boot 연동**: `setup_termux_boot.sh` 스크립트를 통해 스마트폰 부팅 시 Termux:Boot로 루시 웹 백그라운드 서비스 및 자동 Sync 데몬이 자동 시작된다.
- **폰 ↔ PC 1-Click / 양방향 자동 동기화 (자가치유 Self-Healing)**:
  - **부팅 시 자동 Pull**: PC 및 스마트폰 루시 시작/부팅 시 원격 변경사항을 자동으로 Pull.
  - **대화 중 자동 Push**: 대화 속 마무리/저장 키워드("수고했어", "기억해줘", "저장해", "고생했어" 등) 입력 시 또는 메모리 도구(`remember`, `add_todo`, `add_event` 등) 실행 시 자율적으로 `git push`하여 양방향 동기화.
  - **오프라인 푸시 큐 & 자가치유**: 네트워크 단절 시 변경사항이 `pending_sync.json` 오프라인 푸시 큐에 안전하게 대기하며, 인터넷 재연결 시 자동으로 Push를 재시도하고 충돌 발생 시 자가치유(Self-Healing) 로직으로 원활히 동기화.

## 명령어 (터미널)

일 시키기:
- `/일 <시킬 일>` — 여러 단계짜리 일을 계획→실행→검증→보고까지 끝까지 한다. "알아서 다 해줘" 같은 말로도 발동.
- `/컴퓨터 <시킬 일>` — 화면을 보면서 진짜 마우스·키보드로 직접 조작한다(메모장·유니티·웹사이트 등). 시작 전 항상 확인을 받고, 웹(폰)에서는 안전상 금지.
- `/감시 <조건>` — 화면을 계속 지켜보다가 조건이 이루어지면 알려준다(예: 빌드 끝나면). `/감시 중지`로 끝냄.

보고 듣기:
- `/화면 <질문>` — 지금 화면을 찍어서 봐준다. 듀얼 모니터 전체를 보려면 "모니터 둘 다"라고 말할 것.
- `/보기 <그림파일>` — 그림을 보여준다. 파일명만 말해도 바탕화면·사진 폴더에서 찾는다.
- `음성` (또는 `/v`) — 한 마디 음성 입력. 말하고 엔터.
- `/음성모드` — 연속 음성 대화. 말이 끝나면 알아서 답하고 다시 듣는다. "그만" 또는 엔터로 종료. `/음성모드 시험` = 장치 목록+마이크 음량 측정(문턱값 맞추기용). **어느 마이크로 들을지는 config `voice.device`**(이름 일부, 지금은 "Buds"=Galaxy Buds) — 그 장치가 없으면 윈도우 기본 장치로 자동 폴백(장치 번호가 바뀌어도 이름으로 찾음). 시작할 때 "듣는 장치: ○○"를 먼저 보여준다. **⭐자동 귀 찾기**: 말했는데 첫 침묵으로 처리되면 루시가 "마이크를 찾아볼게요"라며 모든 마이크를 동시에 열고 한 번 더 들어, 목소리가 들리는 장치로 스스로 갈아타고 설정에 저장한다 — **새 헤드셋·유선 이어폰을 꽂아도 설정 없이 됨**(스피커 되울림 '스테레오 믹스'는 후보에서 제외, 끄려면 `talk.auto_device: false`). 버즈 마이크는 수준 100이어도 아주 조용해서(말소리 RMS 24~114, 자동 게인이 출렁임) 문턱을 `min_threshold 25`·`noise_mult 2.5`로 맞춰 둠 — 2026-07-15 사용자 육성으로 틀린 장치→자동 발견→갈아타기→받아쓰기까지 전 과정 검증. ⚠️버즈는 유휴 몇 분이면 블루투스가 끊긴다 — 그때는 다시 착용/연결.
- `/읽기` — 답을 소리로 읽어주기 켬/끔. `/읽기 목록`, `/읽기 <목소리 이름>`, `/읽기 엔진 구글|윈도우`, **`/읽기 볼륨 <0~100>`**(목소리 크기 조절 — 예: `/읽기 볼륨 50`=절반, `0`=무음, `100`=원음. 멜로·구글·윈도우 목소리 모두 적용. **"목소리가 너무 크다/작다"는 윈도우 볼륨이 아니라 이 명령으로 조절한다.** 100을 넘기면 소리가 깨질 수 있어 그때는 장치 볼륨을 쓰는 게 낫다). 읽는 중 아무 키나 누르면 즉시 조용해짐.

정보:
- `/브리핑` — 수동 브리핑 즉시 받기(일정·안 읽은 메일·날씨·할 일·뉴스). (⚠️부팅/로그온 시 자동 브리핑은 꺼져 있으며, '/브리핑' 명령어를 직접 부를 때만 켜집니다)
- `/유튜브 <주소>` — 영상 자막을 요약하고 지식 창고에 넣는다(영상은 다운로드 안 함).
- `/검증 <질문>` — 두뇌 둘에게 따로 묻고 답을 대조한다(중요한 사실 확인용).

관리:
- `/벤치` — 두뇌들 성능을 실측해 **순서**를 다시 매기고 적용. (한 달에 한 번 새벽에 자동으로도 재는데, 그때는 **보고만** 하고 적용은 안 한다 — 순위가 달라졌으면 `/상태`가 알려줌)
  - ⛔**deep(어려운 질문 담당)은 벤치가 건드리지 않는다 — 사람이 config.json에 손으로 적는다**(2026-07-19 세션65 사용자 결정). 옛 규칙은 '만점 중 **가장 느린** 모델'에게 deep을 줬는데, **'느림'은 깊이 생각한다는 증거가 아니었다**: 그렇게 뽑힌 Gemini는 평균 9.0초·최대 26.8초에 한도 실패 9건이었고 느린 이유가 인프라 지연·한도 스로틀링이었다. 그런데 pick_order가 어려운 질문마다 이걸 맨 앞으로 당겨 **버벅임과 한도 소진이 동시에** 터졌다(호출 1위 49회). ⭐애초에 **벤치의 3과제(검색·도구2개·추론)는 '어려운 질문 능력'을 재지 않는다** — 재지도 않은 것을 결과로 추론하면 안 된다.

## 어려운 질문을 '깊게' 생각하는 방식 (세션70, 2026-07-22)

루시는 **쉬운 질문**엔 빠른 주력으로 즉답하고, **어려운 질문**(길거나 "왜·어떻게·설계·버그·비교…" 같은 말이 든 질문)에만 아래 4중 장치를 켠다. 전부 config `deliberate`로 끌 수 있고, 쉬운 질문·이미지 보는 턴엔 **안 켜져서** 무료 한도·속도를 그대로 아낀다.

1. **추론 모드(reasoning)** — `deliberate.reasoning`. 어려운 질문에서 그 두뇌에 '더 깊게 생각하라'는 설정을 얹는다. config의 두뇌별 `reasoning` 필드로 지정: `{"reasoning_effort":"high"}`(gpt-oss-120b·glm-5.2·mistral-medium-3.5, OpenAI 규격) 또는 `{"system":"detailed thinking on"}`(nemotron-3-super, 시스템 지시로 켜는 방식). **⭐400 안전망**: 어떤 두뇌가 추론 인자를 거부(400/422)하면 **그 두뇌를 버리지 않고** 인자만 빼서 같은 두뇌로 다시 부른다(이번 실행 동안 그 두뇌엔 추론 인자를 다시 안 얹음 — `_no_reason`). 그래서 추론 인자를 새로 붙여도 **답을 못 받는 일은 절대 없다**. ⚠️**high는 느리다** — 세션70 실측: 사소한 "17+25"에도 glm-5.2 114초·mistral 79초(gpt-oss는 0.8초). 그래서 **깊은 두뇌 순서를 빠른 것부터**(Cerebras→gpt-oss→nemotron→glm→mistral) 둬서 평소엔 앞의 빠른 추론 두뇌가 답하고, 느린 둘은 뒤 폴백으로만 걸리게 했다.
2. **deep 표시 손질** — 강한 추론 두뇌 5개(Cerebras zai-glm-4.7·gpt-oss-120b·nemotron-3-super·glm-5.2·mistral-medium-3.5)에 `deep=true`. 어려운 질문이면 pick_order가 이들을 앞으로 당긴다(예전엔 nemotron 1개뿐이라 라우팅이 거의 안 먹었다).
3. **독립 감수(자가 검증)** — `deliberate.review_independent`. 답을 내보내기 전 감수는 원래도 했지만, 이제 **답을 낸 두뇌 말고 다른 두뇌**가 검토한다(자기 답 자기 검토는 같은 착각을 넘기기 쉬움). 답한 두뇌를 순서 맨 뒤로 미뤄, 다른 두뇌가 다 막혔을 때만 자기가 검토. **호출 수는 그대로**(감수 1회).
4. **분해 지시(decompose)** — `deliberate.decompose`. 여러 갈래가 섞인 큰 질문(길이 140자↑ 또는 어려운 키워드 2개↑ 또는 "그리고/각각/단계" 여러 개)이면, "하위 2~5개로 쪼개 각각 풀고 마지막에 종합하라"는 지시를 한 줄 더 얹는다(추가 호출 없음).

⚠️**추론 인자 형식은 두뇌마다 다르다** — 새 두뇌에 `reasoning`을 붙일 땐 규격 확인 후 붙이되, 틀려도 400 안전망이 받아낸다(다만 그 두뇌는 그날 추론 없이 돈다). ⚠️Groq(qwen3)·Cerebras·로컬 등엔 아직 `reasoning`을 안 붙였다(빠른 주력/최후보루는 그대로 빠르게 두려고). 라우팅 알림 줄에 `+ 깊게 생각`이 뜨면 추론 모드가 켜진 것.
- `/점검` — 자가진단·수리(멜로 서버·Ollama·알림 스케줄러·구글 연동과 **토큰 권한**·**웹 화면 서버**·**C: 디스크 여유**·**받아쓰기 키(Groq)**·**ffmpeg**·**Tailscale 외부 접속**·**두뇌 조용한 고장**(세션64 — 폴백이 가려주는 만성 실패)·**죽은 두뇌**(세션75 — 아래)). 꺼진 서버·꺼진 Tailscale은 직접 켠다.
  - **[죽은 두뇌 경보](세션75 · doctor 11종째)** — 조용한 고장 경보는 **불려본 두뇌만** 본다. 그런데 폴백 사슬은 위가 건강하면 아래를 안 부르니, 다섯 번째 두뇌가 공급자에게서 폐기돼도 호출이 0회라 문턱(4회)에 영영 안 닿는다. **위가 건강할수록 더 안 보이고, 드러나는 순간은 예비가 가장 필요한 때다.** 그래서 주 1회 새벽에 **최근 거의 안 불린 두뇌에만** 짧은 인사를 보내 생사를 확인한다(`brainprobe.py` → `memory/brain_probe.json`, `/점검`은 그 기록을 **읽기만** 해서 시작이 안 느려진다).
  - ⚠️**죽음과 못 잰 것을 구분한다** — 404·폐기만 '죽음'이고, 429(한도)·타임아웃은 **판단 보류**다(내일이면 풀리는 걸 죽었다고 적으면 멀쩡한 두뇌를 버린다). 죽은 두뇌를 자동으로 지우지는 않는다 — 모델 교체는 사람이 config.json에서.
  - 🚨**실측(2026-07-23)**: Groq이 `qwen/qwen3-32b`를 폐기해 404를 돌려주는데도 순위 5위에 그대로 남아 있었고, 조용한 고장 경보는 "만성 고장 없음"이라 답했다. 이 기능이 그걸 잡아냈다.
- `/상태` — 가계부(두뇌별 사용량·쿨다운, 기억·교훈·지식 개수, 새벽 일과 실행 여부). **[계측]** 줄에서 오늘 두뇌별 **평균·최대 응답시간**, **폴백 횟수**(주력이 못 답해 예비로 내려간 횟수), **실패 내역**(한도·길이초과·끊김 등 종류별)을 본다 — "요즘 느려/이상해"의 근거 자료(memory/metrics.json에 14일 보관).
  - **[자동 후순위](세션64)** — 계측을 보고 **만성적으로 실패하거나 유독 느린 두뇌를 이번 실행 동안만 뒤로 미룬다**(밀린 두뇌와 이유가 이 줄에 그대로 보인다). ⚠️**config.json은 절대 안 고친다** — 사람이 정한 순위를 조용히 덮어쓰지 않기 위해서다. 최후의 보루(로컬 Ollama)는 인터넷이 끊겼을 때의 마지막 답이라 **자리를 지킨다**. 눈 전용처럼 부른 쪽이 순서를 직접 준 경우엔 개입하지 않는다. 문턱은 보수적(최근 3일·6번 이상 불린 두뇌만·실패율 50% 이상, 또는 다른 두뇌 중앙값의 3배이면서 15초 넘게 느림) — 표본이 적은 두뇌는 아예 판단하지 않는다. 끄기: config `metrics.auto_demote=false`.
  - **[조용한 고장 경보](세션64)** — 특정 두뇌만 계속 죽는데 **폴백 사슬이 매번 받아내서 사람은 눈치채지 못하는** 상태를 잡아 알린다(최근 3일 4번 이상 중 60% 이상 실패). `/상태`에도 뜨고, **새벽 자가 점검(doctor 10종째)**에도 들어가 있어 사용자가 안 물어봐도 걸린다. 고치는 건 사람 몫(키 재발급·모델 교체는 상의할 일).
- `/지식갱신` — 클로드 노트를 지식 창고로 다시 동기화.
- `/문서색인` — PC 문서(바탕화면·문서·다운로드) 검색 색인을 다시 만든다.
- `/기억정리` — 장기기억 병합·만료 정리(미리보기 보고 y/N).
- `/교훈` — 실수 노트 보기. `/교훈 삭제 <말>`.
- `/복습` — 어제 대화를 되읽고 스스로 교훈을 뽑는다.
- `/공부 [주제]` — 스스로 웹 조사해서 지식 창고에 노트를 만든다(주제 없으면 스스로 고름).
- `exit` / `종료` — 끝내기. 기억할 만한 사실을 자동으로 골라 저장한다.

    - **한글(.hwpx) 만들기 신설** — 제목·소제목·글머리표·문단. 표는 아직 글줄로 펴진다. 구형 .hwp로는 못 만든다(한글에서 열어 다른 이름으로 저장). ⚠️본문이 글자모양·문단모양을 **번호로만** 가리키고 실체는 header.xml에 있어서, 번호 하나만 어긋나도 한글이 파일을 통째로 거부한다 — docs.py의 charPr/paraPr ID는 header와 본문이 **같이** 움직여야 한다. ⚠️mimetype은 zip 첫 항목이며 **무압축**(OCF 규약).

  - **격리·안전**: 코딩 도구는 `workspace/` **밖을 절대 못 건드린다**(바탕화면·문서 등 진짜 파일은 안전 — 경로 탈출 차단). 파일 쓰기·수정은 이 폴더 안이라 확인 없이 하지만, **실행(code_run)만은 프로젝트마다 이번 세션에 처음 한 번 y/N 확인**을 받는다(그 뒤 같은 프로젝트는 고쳐가며 몇 번을 돌려도 다시 안 물음). 라이브러리가 필요하면 code_install로 pip 설치(설치는 매번 확인).
  - 완성되면 "workspace/<폴더>/main.py에 만들었어요, 이렇게 실행하세요"까지 알려준다. **웹(폰)에서는 code_run이 안 된다**(코드 실행은 PC 터미널에서만 — 아래 안전장치).
- **유니티 C# 개발 (unity_find · unity_new_script · unity_run)**: 루시가 유니티 C# 스크립트를 **맥락 알고 짜고 → 컴파일/테스트로 검증하며 완성**한다. 유니티 C#(UnityEngine 참조)은 코딩 작업실로는 못 돌리므로, 이 세 도구가 유니티 C#을 다루는 길이다. 루시가 도는 순서:
  1. **unity_find**(project, query) — 프로젝트 Assets의 `.cs`를 **지금 바로** 훑어 기존 클래스·메서드·필드를 파일:줄로 찾는다("Player가 어떻게 생겼지"). 색인이 아니라 실시간이라 방금 고친 것도 잡힌다 → 환각 감소.
  2. **unity_new_script**(project, name, kind) — **컴파일 되는 골격**을 프로젝트에 만든다(사용자 확인 후). kind: `mono`(MonoBehaviour, 기본)·`scriptable`(ScriptableObject)·`editor`(EditorWindow)·`test`(EditMode 테스트+어셈블리까지)·`plain`. 기본 위치 Assets/Scripts. 내용은 edit_document로 채운다.
  3. **unity_run**(project, [tests / method]) — 유니티를 **창 없이(배치모드)** 띄워 컴파일·테스트. **컴파일 에러는 `파일(줄,칸) CS코드: 메시지`로 정리해서** 돌려주니 그걸 보고 고쳐 다시 돌린다. `tests`='EditMode'/'PlayMode'=테스트(통과/실패 수 요약), `method`='Class.Method'=그 정적 메서드(빌드 스크립트 등), 둘 다 없으면 컴파일 점검.
  - project는 별칭(**saladfarm**=식단 생명체 게임, **onlyuprat**) 또는 폴더 경로(config.json `unity` 블록).
  - **unity_status** — unity_run은 에디터가 열려 있으면 실패하는데, 이건 **에디터를 켜둔 채** Editor.log만 읽어 "지금 컴파일 에러 있나"를 빠르게 본다("에디터의 마지막 컴파일" 기준, 정밀 검증은 unity_run). "유니티 에러 났나 봐줘"에 가볍게. (참고: unity_run/build는 에디터가 프로젝트를 열고 있으면 **헛부팅 없이** 즉시 "에디터 닫으라"고 알려준다 — Temp/UnityLockfile 감지.)
  - **unity_health**(세션64) — **작업 대상 프로젝트 건강 감시**. 등록된 유니티 프로젝트(config `unity.projects`, 같은 폴더를 가리키는 별칭은 한 번만)를 하나씩 **배치모드로 열고 닫아** 지금 컴파일 되는지 확인한다. 에디터가 그 프로젝트를 열고 있으면 **정적 점검으로 자동 대체**(최신 .cs mtime vs `Library/ScriptAssemblies` 최신 .dll mtime — 코드가 더 새것이면 `⚠stale`)라 잠금 사고가 없다. 결과는 `memory/unity_health.json`에 남고, **새벽 06:00 일과가 자동 실행**해 **아침 브리핑에 문제가 있을 때만 한 줄**로 실린다(이상 없으면 브리핑은 그 줄을 통째로 건너뜀). "샐러드팜 괜찮아?"·"프로젝트 점검해줘"에 쓴다. 끄기·시각은 config `daily.unity_health`(enabled·at·timeout).
    - **감시 제외**: config `unity.health_skip`에 적은 별칭은 자동 감시에서 뺀다 — 더 개발하지 않는 프로젝트의 에러를 매일 아침 읊으면 경보만 무뎌지기 때문. **2026-07-18 사용자 결정으로 `saladfarm`·`dietcreature`가 제외됨**(샐러드팜은 더 진행하지 않음). ⚠️별칭은 살아 있으니 "샐러드팜 점검해줘"처럼 **직접 시키면 그대로 된다**.
    - ⚠️**왜 unity_status가 아니라 배치인가**: Editor.log는 PC에 **하나뿐인 전역 로그**라 어느 프로젝트 것인지 알 수 없다(실측: 로그가 엉뚱한 `D:\test\My project` 것이었음). 프로젝트별 상태는 그 프로젝트를 실제로 열어봐야 안다.
    - ⚠️doctor 9종은 **루시 자기 인프라**만 본다 — 작업 대상 프로젝트가 깨진 것은 이 도구가 본다(세션63에 saladfarm 패키지가 CS0115로 깨져 배치 작업이 전멸했는데 루시는 몰랐던 실측 구멍).
  - **unity_audit** — 유니티를 안 띄우고 프로젝트 파일만 스캔해 문제를 잡는다: **깨진 스크립트 참조**(누락 컴포넌트로 프리팹/씬이 깨진 것)·**큰 텍스처**(빌드 용량)·`.meta` 누락. "리팩터했더니 프리팹 깨진 것 같아, 감사해줘" / "빌드 용량 큰 거 뭐야"에 쓴다. 빠르고 읽기전용.
  - **unity_build** — APK·AAB를 배치모드로 **빌드**한다. "apk 빌드해줘"(kind=apk)·"aab 뽑아줘"(kind=aab)·개발용(dev). saladfarm은 config에 빌드 메서드가 등록돼 있고, 다른 건 method='Class.Method'로 지정. 오래 걸리고 확인받으며 에디터는 닫혀 있어야 한다.
  - **정찰 5종(세션61 — 전부 유니티 안 띄움·읽기전용·확인 없음·에디터 켜둔 채 됨)**:
    - **unity_scene**(project, [path]) — 씬(.unity)·프리팹(.prefab)의 **게임오브젝트 계층+컴포넌트 트리**를 YAML 파싱으로 본다. MonoBehaviour는 스크립트 클래스 이름으로 풀어 보여준다(패키지 컴포넌트 GraphicRaycaster 등 포함). path 없으면 씬·프리팹 목록. "Farm 씬에 뭐 있어?" / "Creature 프리팹 구조 봐줘".
    - **unity_refs**(project, [asset]) — 에셋 **guid 참조 추적**. asset을 주면 그걸 참조하는 씬·프리팹·머티리얼 목록("이 스크립트 어디서 써?"), 비우면 **미사용 에셋 후보** 보고서(크기순, Editor·Resources·Plugins 제외). ⚠️코드에서 이름으로 로드(Resources.Load)하는 건 못 잡으니 지우기 전 unity_find로 이중 확인.
    - **unity_settings**(project) — 제품명·버전(bundleVersion)·안드로이드 버전코드·번들ID·에디터 버전·**빌드에 포함된 씬 목록**·define 심볼·패키지 요약. "버전 몇이야?" / "빌드에 씬 뭐 들어가?".
    - **unity_log**(project, [source]) — 게임을 돌리다 난 **런타임 예외**(NullReference 등)를 로그에서 종류별 횟수+스택으로 집계한다(unity_status는 컴파일 에러만 봄 — 그 빈틈). source=editor(기본, 에디터 플레이)·player(빌드된 게임의 Player.log, 회사·제품명은 설정에서 자동으로 읽음). "게임 실행하다 에러 났어".
    - **unity_outline**(project, [path]) — C# 코드의 **뼈대**(클래스·메서드 시그니처·직렬화/공개 필드)를 뽑는다. unity_find=낱말 위치 검색, 이건 구조 개요. path 없으면 프로젝트 전체 파일별 요약(클래스·메서드 수). 큰 파일을 통째로 안 읽고 구조부터 파악할 때.

    - **unity_snapshot**(project, action, [id], [file]) — 씬·프리팹·에셋(.asset)·설정을 통째로 **스냅샷**(action=take, 확인 없음·1초 미만·최근 15개 보관, my-agent/memory/unity_snapshots/)·목록(list)·**복원**(restore, 확인 후 — **복원 직전 상태도 자동 백업**되므로 복원 자체도 되돌릴 수 있음). file에 이름을 주면 그 파일만 복원. 큰 수정 전 "찍어둬" / 사고 후 "아까로 되돌려줘".
    - **unity_diff**(project, path, [path2 | snapshot]) — 씬·프리팹이 **스냅샷(기본 최신)이나 다른 파일과 뭐가 다른지**: 추가/삭제된 게임오브젝트, 바뀐 컴포넌트의 값(−/+ 줄). "어제랑 뭐가 달라졌어" / 복원 판단용. 읽기전용.
    - **unity_yaml_edit**(project, path, find, replace, [all]) — 씬·프리팹·에셋의 **직렬화 값을 기계적으로 치환**(자동 백업+사용자 확인). '프리팹 기존 컴포넌트에 새 필드=기본값 구워짐 → YAML에 명시' 같은 일이 딱 이 용도. ⚠️에디터가 그 파일을 열고 있으면 에디터 저장이 이 수정을 덮어쓸 수 있다 — 닫고 하는 게 안전.
    - **unity_build_report**(project) — **마지막 빌드의 용량 분석**: 카테고리별(텍스처·DLL·사운드…) 크기, 큰 에셋 상위, **직전 빌드 대비 증감**(이력 10회 추적). unity_build로 빌드하면 로그가 자동 저장돼 언제든 조회된다(에디터 GUI 빌드는 Editor.log가 남아 있는 동안만). "APK 왜 커졌어".
    - **unity_sprites**(project, [folder]) — **스프라이트 임포트 감사**: 같은 폴더인데 크기 이탈(128px 통일 규칙 깨짐 — 통일 무리 3장 이상인 폴더만 지적)·PPU 불일치·스프라이트에 밉맵 켜짐·maxTextureSize 초과 원본. 아트 반입 후 점검. 읽기전용.
    - **unity_tex_fix**(project, [folder], [max_px]) — 감사가 잡은 큰 텍스처의 **수리 짝**: "텍스처 용량 낮춰줘" 하면 maxTextureSize가 max_px(기본 1024)를 넘는 .meta를 **일괄 하향**(플랫폼 오버라이드 포함). **원본 그림 파일은 불변**·원본 픽셀이 이미 작은 건 건너뜀·자동 백업(memory/unity_snapshots/…/edits/)·후보 개수를 보여주고 y/N. ⚠️화질 트레이드오프가 있는 일이니 배경처럼 큰 그림은 낮추기 전에 생각할 것. ⚠️에디터 열려 있으면 거절(수정이 덮어써지는 사고 방지).

## 두뇌(답변 생성)와 "모든 모델이 실패"

루시는 여러 두뇌(AI 모델, `/상태`로 목록 확인)를 우선순위대로 시도한다. 위쪽 클라우드 두뇌가 사용 한도에 걸려 잠깐 쉬면 자동으로 다음 두뇌로 내려가고, **맨 마지막에는 인터넷이 없어도 되는 로컬 두뇌(Ollama)**가 받친다.

- 클라우드 두뇌가 전부 막혀도 로컬 두뇌가 답하므로 `[모든 모델이 실패했습니다]`는 거의 안 나온다. 로컬 두뇌를 부르기 직전에 루시가 **Ollama가 꺼져 있으면 자동으로 다시 켜서(약 1~2초)** 부른다.
- 로컬 두뇌는 느릴 수 있다(최대 1~2분) — 실패 대신 **답이 나오게** 하는 게 목적이다.
- 그래도 "모든 모델이 실패"가 계속 뜨면 **Ollama가 설치되지 않았거나 완전히 꺼진 것**이다. `/점검`을 하거나 터미널에서 `ollama serve`를 한 번 켜면 된다.
- 특정 두뇌가 왜 쉬는지는 `/상태`의 쿨다운·[계측] 실패 내역에서 볼 수 있다.
- **도구 명세는 두뇌마다 다른 양이 실린다**(세션75). 기본은 전부(77종·약 15,700토큰)이고, `context ≤ 16384`이거나 **`tool_budget: "compact"`**인 두뇌에는 요약본에서 질문과 관계있는 것만 골라 약 1,800토큰만 싣는다. 둘은 **다른 이유로** 줄이는 것이다 — `context`는 담을 자리가 좁아서, `tool_budget`은 **분당 토큰 한도(TPM)**가 좁아서. Groq 무료 티어가 후자라, 이 값 없이 Groq 두뇌를 넣으면 질문 한 번에 413으로 죽는다(후보 3종 전부 실측).
- ⭐**"이 모델은 413이라 쓰지 말 것"이라고 적어 둔 메모를 의심해 볼 것**(세션75) — `gpt-oss-120b`를 그렇게 금지해 뒀는데, 실은 모델 탓이 아니라 명세 크기 탓이었다. 압축해 넣으니 도구호출 4/4 정답에 0.5~1.0초로 후보 중 가장 깨끗했다.
