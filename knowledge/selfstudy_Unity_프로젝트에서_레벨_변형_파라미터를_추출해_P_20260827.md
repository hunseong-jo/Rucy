# Unity 프로젝트에서 레벨 변형 파라미터를 추출해 PPT 기획서의 스테이지 변형 내용과 자동 비교·검증하는 워크플로우 설계 — 루시 자가 학습 노트 (2026-08-27)

> 루시가 스스로 웹을 조사해 정리한 노트입니다. 검증되지 않았을 수 있으니
> 수치·사실을 인용할 때는 출처를 함께 말할 것.

## 핵심 워크플로 설계 포인트

### 1. Unity 2022.2 테크 스트림 활용  
- **생산성 워크플로 개선**  
  - 빠른 Play‑Mode 진입, 파일 가져오기 속도 향상 등으로 반복 테스트 시간이 단축【출처 1】  
- **시각적 검색 쿼리**  
  - 에디터 내에서 “Transform” 등 특정 컴포넌트를 가진 오브젝트를 한 번에 검색·선택 가능【출처 1】  
- **패키지 관리자 다중 선택**  
  - 여러 스크립트·패키지를 동시에 열어 수정·배포할 수 있어 파라미터 추출 로직을 별도 패키지화하기 용이【출처 1】  
- **프레임 타이밍 매니저**  
  - 플랫폼에 관계없이 성능 병목을 확인·조정 가능 → 추출된 변형값이 실시간 성능에 미치는 영향 검증에 활용【출처 1】

### 2. 레벨 변형 파라미터 자동 추출 방법 (가능한 범위)  
| 단계 | 활용 Unity 기능 | 기대 효과 |
|------|----------------|-----------|
| 객체 식별 | 시각적 검색 쿼리 → `Transform` 컴포넌트 검색 | 레벨에 포함된 모든 오브젝트를 일괄 선택 |
| 데이터 수집 | 에디터 확장 스크립트 (C#) → `transform.position/rotation/scale` 읽기 | 코드가 에디터와 독립적으로 실행 가능 |
| 파일 출력 | `System.IO` 이용 CSV·JSON 저장 | 외부 툴(PPT, Excel 등)과 데이터 연동 용이 |
| 검증·비교 | CSV → 파이썬/PowerShell 등으로 PPT 스테이지 표와 매칭 | 자동화된 차이점 리포트 생성 |

> 위 흐름은 Unity 에디터가 **확장 가능**하고 **생산성 워크플로**가 강화된 점을 기반으로 설계되었습니다(출처 1).  

### 3. 규모 확대 시 코드 설계 원칙  
- **작은 단위로 분리** – 파라미터 추출 로직을 독립 모듈(예: `LevelParamExtractor`)로 구현하고, 필요 시 패키지로 배포【출처 3】  
- **반복 설계 검토** – 프로젝트 성장에 따라 추출 대상(새 레벨, 새 오브젝트) 추가 시 모듈만 수정·테스트【출처 3】  
- **기술 부채 최소화** – 초기 설계 시 인터페이스 정의(`IParamProvider`)와 의존성 주입 적용으로 향후 확장·유지 보수 비용 절감【출처 3】
