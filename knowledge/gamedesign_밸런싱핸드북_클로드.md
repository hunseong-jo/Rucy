# 게임 수치·밸런싱 설계 핸드북

작성: 클로드(사용자의 요청으로 집필) · 루시의 밸런싱 보조 역할을 위한 교재
성격: 공개 강의 요약이 아니라 **실무에서 계산하는 법**. 개념은 「게임제작개론 #4 게임 밸런싱」(구승모)을 함께 볼 것.
예제는 사용자의 실제 게임 **샐러드팜**의 수치를 씀 — 추상적인 공식만으로는 적용이 안 되기 때문.

## 0. 밸런싱의 정의 — 뭘 맞추는 일인가

밸런싱은 "숫자를 예쁘게 하는 일"이 아니다. **플레이어가 쓰는 자원(시간·돈·주의력)과 게임이 돌려주는 보상의 교환비를 설계하는 일**이다.

밸런싱 질문은 언제나 이 형태로 환원된다:
- 플레이어가 X를 하면 Y를 얼마나 얻는가?
- 그 Y로 다음 단계에 가는 데 얼마나 걸리는가?
- 그 시간이 **지루한가, 조급한가, 적당한가?**

세 번째 질문은 수식으로 답할 수 없다. 수식은 "얼마나 걸리는지"까지만 알려준다.
**그래서 밸런싱은 계산 → 체감 확인 → 재계산의 반복이다. 계산만 하고 끝내면 반드시 틀린다.**

## 1. 재화 경제 — 수도꼭지와 배수구 (Sources & Sinks)

모든 재화는 **어디서 생겨나(source) 어디로 사라지는지(sink)** 짝이 맞아야 한다.

- **Source(수급)**: 퀘스트 보상, 시간당 생산, 판매, 출석 보상, 광고 시청
- **Sink(소모)**: 상점 구매, 강화 비용, 수리비, 확장 비용, 수수료

### 인플레이션은 sink가 모자랄 때 일어난다
source만 있고 sink가 약하면 재화가 계속 쌓인다. 그러면:
1. 상점의 모든 물건이 "언젠가 자동으로 살 수 있는 것"이 된다 → 구매 결정이 의미를 잃는다
2. 신규 유저와 고참 유저의 격차가 손쓸 수 없이 벌어진다
3. 나중에 재화를 회수하려 하면 유저가 "내 돈 뺏겼다"고 느낀다 → **회수는 지급보다 100배 어렵다**

**설계 원칙: 재화를 풀기 전에 그 재화가 사라질 구멍부터 판다.**

### 수지 계산의 기본형

```
일일 순증 = (일일 수급 합계) − (일일 소모 합계)
```

이 값이 **양수로 계속 유지되면 인플레이션**이다. 건강한 경제는 보통:
- 초반(신규): 순증이 크게 양수 (성장의 쾌감)
- 중반: 순증이 0 근처에서 진동 (선택의 긴장)
- 후반(고참): 목표 아이템이 비싸서 며칠 모아야 함 (장기 목표)

### 시간당 가치라는 기준선
경제를 설계할 때 **모든 재화를 "플레이 1시간 = 골드 얼마"로 환산**해두면 비교가 가능해진다.

샐러드팜 예:
- 농장 체류 시 분당 5 경험치 (매칭 식단이면 ×2 = 10)
- 1시간 체류 = 300~600 경험치
- 아이템 1개 = 500 경험치

즉 **아이템 1개 ≈ 농장에 1~1.7시간 머무는 것과 같은 가치**다.
만약 상점에서 아이템을 100골드에 판다면, 골드의 시간가치는 **1골드 ≈ 36~60초**가 된다.
이 환산이 되어야 "이 아이템 5000골드는 비싼가?"에 답할 수 있다 → **약 50~83시간. 명백히 너무 비싸다.**

## 2. 성장 곡선 — 레벨업에 얼마나 걸리게 할 것인가

### 세 가지 기본 곡선

| 곡선 | 필요치 공식 | 체감 | 쓰는 곳 |
|---|---|---|---|
| **선형** | `a + b·L` | 후반이 지루하지 않음. 끝이 쉽게 옴 | 레벨 상한이 낮은 캐주얼 |
| **지수** | `a · r^L` | 후반이 급격히 벽 | 과금 유도형, 장기 MMO |
| **다항(제곱)** | `a · L^k` | 완만하게 무거워짐. 가장 무난 | 대부분의 게임 |

### 샐러드팜의 실제 곡선 (선형)
```
필요 경험치(레벨 L) = 1000 + 200·L
아이템 1개 = +500 경험치
```

레벨 L을 올리는 데 필요한 아이템 수 = `(1000 + 200·L) / 500 = 2 + 0.4·L`

- 레벨 1 → 2.4개
- 레벨 5 → 4개 (성장 단계 도달)
- 레벨 10 → 6개 (진화 단계 도달)

**누적**: 레벨 1에서 시작하므로 레벨 10까지는 **9번의 레벨업**이다(10번이 아니다 — 여기서 한 칸 틀리기 쉽다).
Σ(1000 + 200·L), L=1..9 = 9,000 + 200×45 = **18,000 경험치 = 아이템 36개**

이게 "적당한가?"는 아이템 획득 속도를 알아야 답할 수 있다.
날씨 자동 경험치가 분당 5라면, 레벨 10까지 순수 방치로는 **18,000 / 5 = 3,600분 = 60시간**.
식사 촬영으로 아이템을 얻는 게 주 경로라면 이 60시간은 "촬영 안 하면 이만큼 느리다"는 **페널티 기준선**으로 기능한다. 방치 경로가 주 경로보다 빠르면 게임의 핵심 루프(식사 촬영)가 죽는다 — **항상 주 경로가 가장 빨라야 한다.**

### 검증하는 법
곡선을 정했으면 반드시 **표로 펼쳐서 눈으로 본다.** 공식만 보고 있으면 후반의 벽을 못 느낀다.

```python
# 레벨 1~20까지 누적 필요 경험치와 예상 소요 시간
need = lambda L: 1000 + 200*L
total = 0
for L in range(1, 21):
    total += need(L)
    items = total / 500          # 아이템 개수
    hours = total / (5 * 60)     # 방치 시간(분당 5)
    print(f"Lv{L:2d}  누적 {total:6,}xp  아이템 {items:5.1f}개  방치 {hours:5.1f}시간")
```

**루시에게: 성장 곡선 질문이 오면 반드시 이렇게 `run_python`으로 표를 뽑아서 보여줄 것. 공식만 말하면 도움이 안 된다.**

## 3. 확률 설계 — 기대값만 보면 반드시 사고가 난다

### 기대값(EV)
```
기대값 = Σ (확률 × 가치)
```
가챠 1회에 100골드, 1% 확률로 10,000골드짜리가 나온다면 EV = 100골드. 수지는 맞는다.

### 그런데 기대값은 거짓말을 한다
확률 p로 성공하는 시도를 **n번 했을 때 한 번도 성공 못 할 확률**은 `(1-p)^n`이다.

p = 1%일 때:
- 100회 뽑아도 꽝일 확률 = 0.99^100 ≈ **36.6%**
- 300회 뽑아도 꽝일 확률 = 0.99^300 ≈ **4.9%**

즉 **"평균 100번이면 나온다"는 말은 3명 중 1명은 100번 뽑고도 못 얻는다는 뜻**이다.
그 사람은 게임을 접는다. 기대값은 그 사람을 보여주지 않는다.

### 그래서 필요한 것: 천장(Pity)
- **하드 천장**: n회째에 확정 지급. 최악의 경험에 바닥을 깐다.
- **소프트 천장**: 실패할수록 확률이 오름 (예: 50회 이후 회당 +1%p)

**설계 원칙: 확률을 쓰려면 최악의 경우를 먼저 계산하고, 그 최악이 견딜 만한지 본다.**
견딜 수 없으면 천장을 넣는다. 넣기 싫으면 확률을 쓰지 않는다.

### 분산을 보는 법
```python
import random
def simulate(p, trials=10000):
    counts = [next(i for i in range(1, 10000) if random.random() < p) for _ in range(trials)]
    counts.sort()
    print(f"중앙값 {counts[len(counts)//2]}회 · 상위10% 운나쁨 {counts[int(len(counts)*0.9)]}회 · 최악 {counts[-1]}회")
simulate(0.01)
```
**루시에게: 확률 설계 질문엔 반드시 시뮬레이션을 돌려 "운 나쁜 10%가 몇 번 만에 얻는지"를 같이 보고할 것.**

## 4. 난이도 곡선 — 플로우(Flow)

플레이어의 **실력**은 시간에 따라 오른다. 게임의 **난이도**도 올라야 한다.
- 난이도 > 실력 → **불안·좌절** → 이탈
- 난이도 < 실력 → **지루함** → 이탈
- 둘이 나란히 → **몰입(Flow)**

단, 난이도를 **매끈한 직선**으로 올리면 밋밋하다.
좋은 곡선은 **톱니 모양** — 올렸다가 잠깐 풀어주고(쉬운 구간·보상 구간) 다시 더 높이 올린다.
그 "풀어주는 구간"에서 플레이어는 자기가 강해졌음을 확인한다. **성장의 쾌감은 어려운 구간이 아니라 쉬워진 구간에서 온다.**

힐링 게임(샐러드팜 같은)에서는 난이도 대신 **"기다림"이 긴장의 축**이다. 같은 원리가 적용된다:
기다림이 너무 길면 지루하고, 너무 짧으면 성취가 가볍다. 그리고 **가끔은 빨리 되는 구간**이 있어야 한다.

## 5. 개체 간 밸런스 — 여러 선택지를 어떻게 대등하게 만드는가

캐릭터·유닛·생물이 여러 종류일 때 "다 똑같이 강하게"는 틀린 목표다. 맞는 목표는 **"어느 것을 골라도 후회하지 않게"** 다.

### 세 가지 방법

1. **상성(가위바위보)**: A는 B에 강하고 B는 C에 강하고 C는 A에 강하다.
   → 절대 강자가 없어진다. 대신 **상대를 모르면 선택이 도박**이 된다.

2. **비용 대비 성능(Cost Curve)**: 강한 만큼 비싸게. `성능 = f(비용)` 함수를 하나 정해두고 모든 개체를 그 곡선 위에 올린다.
   → 곡선에서 벗어난 개체가 곧 **OP거나 쓰레기**다. 이걸 표로 만들면 밸런스 붕괴가 눈에 보인다.

3. **역할 분리**: 성능 축을 여러 개로 쪼갠다(공격/방어/속도/유틸). 총합은 같게, 배분은 다르게.
   → "강함"이 상황에 따라 달라져 비교 자체가 무의미해진다. **가장 안전한 방법.**

### 지배 전략(Dominant Strategy)을 찾아라
밸런스 붕괴의 정체는 거의 항상 **"이걸 고르면 항상 이득인 선택지"** 하나다.
밸런싱 리뷰의 첫 질문은 언제나: **"고수는 결국 뭘 고를까? 그게 하나로 정해지면 나머지는 다 장식이다."**

## 6. 밸런싱 리뷰 체크리스트 (기획서를 볼 때 이 순서로 묻는다)

1. **단위가 있는가** — "골드를 많이 준다"는 수치가 아니다. 얼마를, 얼마 만에?
2. **source와 sink가 짝이 맞는가** — 이 재화는 어디서 생겨서 어디로 사라지는가?
3. **시간가치로 환산되는가** — 이 가격은 플레이 몇 시간인가?
4. **주 경로가 가장 빠른가** — 방치·우회 경로가 핵심 루프보다 효율이 좋으면 게임이 죽는다.
5. **최악의 경우를 계산했는가** — 확률이 있다면 운 나쁜 10%는 얼마나 고생하는가?
6. **지배 전략이 있는가** — 결국 하나만 고르게 되지 않는가?
7. **후반이 벽인가 지루한가** — 곡선을 20단계까지 표로 펼쳐 봤는가?
8. **회수 계획이 있는가** — 나중에 이 재화가 넘칠 때 뺄 방법이 있는가? (사후 회수는 거의 불가능)

## 7. 루시가 밸런싱을 도울 때의 원칙

- **숫자를 지어내지 말 것.** 모르는 값은 "이 값이 필요하다"고 물어라. 지어낸 수치로 계산하면 그럴듯한 거짓말이 된다.
- **반드시 `run_python`이나 `calc`로 실제 계산할 것.** 암산으로 답하면 틀린다.
- **표로 펼쳐서 보여줄 것.** 공식 한 줄보다 20줄짜리 표가 낫다.
- **"적당한가?"는 사람이 판단한다.** 루시는 "레벨 10까지 63시간 걸린다"까지 말하고, 그게 긴지 짧은지는 사용자에게 묻는다.
- **힐링 게임 원칙 준수** — 사용자는 숙제성 콘텐츠(데일리 리셋·스트릭·기한)를 명시적으로 거절했다. 밸런싱 제안에 "매일 접속 안 하면 손해" 구조를 넣지 말 것. '기다리면 쌓이는' 방향으로.
