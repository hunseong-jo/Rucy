## 크리처 아트 (DietCreature, [[feature-creature-species]])

> ⚠️ **최신(2026-07-02 세션21): 아트 전면 교체됨.** 아래 절차생성/부속키트/치이카와 리파인 내용은 **옛 이력**이고 지금 파일엔 반영 안 됨(사용자가 도트 아트로 새로 그려 덮음).

### 🎨 32×32 도트 아트로 전면 교체 (2026-07-02 세션21 — ✅ 완료)
- 사용자가 **64종 전부를 직접 도트(픽셀)아트로 제작**해 교체(원본=`C:\Users\user\Downloads\도트변환\`, 파일 128×128로 저장하되 32px 그리드 스타일). 이전 절차생성 아트(둥근 몸+절차 부속)는 폐기됨.
- 통합: `Assets/Art/Creatures/<id>.png`에 PNG만 덮어쓰기(.meta GUID 유지→코드/도감/DB 무수정). 이름 1개 불일치(`worldtree-fairy`→`worldtree_fairy`) 리네임으로 해결. 크기 128×128 동일이라 PPU(110) 유지=농장 스케일 그대로.
- 임포트 설정: **전 64종 filterMode=Point + textureCompression=Uncompressed + mipmap off**(픽셀 선명). MCP 스크립트로 일괄(멱등). 검증: CreatureCatalog.GetSprite 6종 128×128/Point/PPU110 확인, 에러0.
- 원본 백업: scratchpad `creatures_backup_old/`(64개, 세션 임시라 영구보관 아님).
- 관찰: 일부(bd1 등) 옆에 작은 물방울 떠 있음(의도된 디자인/미제거). 
- **TODO(미완)**: 눈감는(깜빡임) 표정 변형본 — 사용자가 아직 안 만듦. 눈 위치가 종마다 다르면 사용자 제작, 일관되면 스크립트로 일괄+런타임 애니 가능(앞서 논의).

### (이하 옛 이력 — 현재 아트엔 미적용)
- **위치**: `Assets/Art/Creatures/<id>.png` (61종, 128x128). 코드로 절차 생성된 스프라이트.
- ⚠️ **생성 스크립트가 프로젝트에 파일로 저장돼 있지 않음** (이전 세션의 script-execute로 일회성 생성, PNG만 남음). 아트 수정은 PNG 픽셀을 직접 보정해야 함.
- 임포트: textureType Sprite, 128px, alphaIsTransparency. Resources 아님 → CreatureCatalog가 CreatureDatabase.asset의 sprite 참조로 로드.

### 🦾 부속(팔/꼬리/발) 바리에이션 추가 (2026-06-28 세션8 — ✅ 완료)
- 사용자 요청: 생물들이 둥근 몸+얼굴만 있어 비슷 → **실루엣 다양화**. 단 "전부 달지 말고 몸만 있는 것도 섞어서 다양하게".
- 방식: 기존 PNG를 0.80배 축소해 여백 만든 뒤, **몸 색을 자동 추출**(opaque·luminance 0.22~0.9 평균, 외곽선=×0.62)해 절차적으로 부속을 뒤 레이어에 그려 합성. id별 **FNV-1a 해시 → 키트 테이블**로 결정.
- **키트 8종**: 0 몸만(plain) / 1 팔내림 / 2 팔올림 / 3 두 발 / 4 말린꼬리 / 5 동그란꼬리 / 6 팔내림+발 / 7 팔올림+뾰족꼬리. 테이블 가중치 `{0,0,0,0,1,1,1,2,2,3,4,4,5,6,7}`로 plain·팔 비중 높임. 팔내림과 꼬리는 한 키트에 안 겹치게(우측 충돌 회피).
- 적용 결과(61종): plain 17 / 팔내림 12 / 팔올림 14 / 발 3 / 말린꼬리 4 / 동그란꼬리 4 / 팔+발 3 / 팔올림+뾰족꼬리 4.
- ⚠️ **원본 백업**: `<project>/art_backup/Creatures/` (61개, Assets 밖이라 미임포트). 재실행/되돌리기는 여기서. plain 종은 원본 그대로 씀.
- ⚠️ 절차 스크립트는 일회성(script-execute, 미저장). 재적용 시 **항상 art_backup 원본 기준**으로 처리해야 중복 축소 안 됨. GUID 보존(같은 .png 덮어쓰기)이라 참조 안 깨짐.
- 미세 잔여: 말린꼬리(curl)가 동그란꼬리(puff)와 비슷하게 보이는 편(원하면 차별화 가능).
- **치이카와풍 리파인 (세션8 후반)**: 사용자가 "팔 너무 크다, 치이카와처럼 작은 팔다리. 단 몇 종은 지금(큰)팔 유지" 요청. 스타일 축 추가:
  - **tiny(치이카와)**: 몸 축소 0.85(덜 줄여 몸 큼)+가는 짧은 팔(r=w*0.05,len=w*0.14)+작은 손발. 대부분(39종).
  - **chunky(기존 큰 팔)**: 몸 0.80+r=w*0.09,len=w*0.16. `Fnv(id+"_arm")%5==0 && 팔보유키트`인 ~20%만(현재 5종: premium4,rare10,rare2,rare5,slime).
  - tail/feet 키트는 tiny만 적용. plain 17종 유지.
  - 최종: chunkyArms 5 / tinyLimbed 39 / plain 17. art_backup 원본 기준 재적용(중복축소 방지).

### 🐰 귀/뿔 상단 클리핑 주의 (2026-06-28 세션5 수정 — ✅ 완료)
- 위로 솟는 부위(토끼 귀 등)를 128px 캔버스 상단 경계에 너무 붙여 그리면 끝이 **평평하게 잘림**.
- 잘렸던 9종(`bm2 bv3 premium4 premium9 pv2 rare4 rare7 rd2 ri3`)을: 그림을 아래로 시프트(하단 빈 여백 범위 내, 좁은귀 10px/넓은귀 6px)해 상단 여백 확보 → 잘린 평평한 끝을 채움색 둥근 캡(반타원, 외곽선 있으면 외곽선 포함)으로 복원하여 해결. 검증: 최상단행 opaque 0. **보정 완료됨.**
- **앞으로 종 추가 시**: 귀/뿔/안테나 등은 상단에 최소 8~10px 여백을 두고 그릴 것.
