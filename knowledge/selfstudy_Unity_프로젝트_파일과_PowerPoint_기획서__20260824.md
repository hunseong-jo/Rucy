# Unity 프로젝트 파일과 PowerPoint 기획서 내용 일관성 자동 검증 도구 설계 — 루시 자가 학습 노트 (2026-08-24)

> 루시가 스스로 웹을 조사해 정리한 노트입니다. 검증되지 않았을 수 있으니
> 수치·사실을 인용할 때는 출처를 함께 말할 것.

## 핵심 사실·수치·방법  

### 1. 기획서 작성 도구  
- **PowerPoint** : 도형·그림 삽입·꾸미기가 쉬워 게임 기획 파트에서 주로 사용(출처 1).  
- **Excel** : 수치·테이블 관리에 활용(출처 1).  

### 2. QA(퀄리티 어슈어런스)의 역할  
- 게임 품질 담당 직종으로, **버그 탐지**뿐 아니라 **기획서와의 차이점 파악**을 수행(출처 2).  
- 차이점 검출은 자동화 검증 도구의 핵심 요구사항이 됨.  

### 3. 프로젝트 매니저(PM)의 역할  
- 개발 업무 조율·팀 운영 총괄(출처 2).  
- 일관성 검증 결과를 기반으로 일정·리소스 재조정에 활용 가능.  

### 4. Unity 프로젝트 조직 베스트 프랙티스  
- **표준 설정** : 팀 전체가 따를 폴더·네이밍 규칙 정의(출처 3).  
- **버전 관리** : Git·SVN 등으로 파일 변동 이력 보관, 변경점 추적 가능(출처 3).  
- **기술·비기술 멤버 모두 이해 가능한 구조** : 문서·코드·에셋을 일관된 방식으로 배치해 자동 검증 로직 적용 용이(출처 3).  

### 5. 일관성 자동 검증 도구 설계 시 활용 아이템  
| 활용 요소 | 근거 |
|---|---|
| **기획서 형식 파싱** | PowerPoint(도형·텍스트)와 Excel(표) 활용(출처 1) → 텍스트·표 추출 API 적용 가능 |
| **차이점 탐지 로직** | QA가 기획서와 실제 구현 차이점 탐색(출처 2) → 자동화 대상 명시 |
| **표준·폴더 규칙 검증** | Unity 프로젝트 조직 표준(출처 3) → 폴더·파일명 일관성 자동 검사 |
| **버전 관리 연동** | 변동 이력 기반 변화 추적(출처 3) → 최신 기획서와 코드/에셋 매핑 검사 |
| **결과 보고와 피드백** | QA·PM이 검증 결과 활용(출처 2) → 자동 알림·대시보드 제공 |  

> **주의**: 위 자료에는 자동 검증 도구의 구체적 구현 방법이나 알고리즘이 제시되지 않음. 따라서 설계 시 **“차이점 탐지”와 “프로젝트 조직 표준”**을 기반으로 자체 로직을 개발해야 함을 유념.
