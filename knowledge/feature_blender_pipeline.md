# 블렌더 3D 아트 파이프라인 (2026-07-15 세션56 검증 완료)

**배경**: 2인 개발이라 사용자가 기획+아트 겸임. "루시한테 블렌더 모델링 시킬 수 있나" → 합의된 분업: **조형(bpy 스크립트)=클로드**(루시 무료 두뇌로는 품질 부족), **반복(변형·렌더·내보내기)=추후 루시 도구화**(edit_video 패턴). 샐러드팜 도트 파이프라인과 같은 분업.

**검증 결과(알약 요원 v1→v3, 3회 반복)**: 조형→헤드리스 렌더 4방향→내 눈으로 검수→수치 수정→FBX까지 완주. 결과물 `Desktop\알약요원_블렌더테스트\`(v3 렌더 4장+fbx+blend+스크립트). 눈높이: 블록아웃·프로토·소품·자리표시자까지 충분, 히어로 아트는 사람 마무리.

## 환경·함정 (실측)
- **블렌더 5.0.1 = `D:\blander\blender.exe`** (폴더명 오타 그대로. winget 목록에도 잡힘). 헤드리스 `--background --python x.py` 클로드 Bash에서 정상(GUI 아님 — 샌드박스 안 걸림).
- ⚠️**렌더 엔진 이름: 5.0은 `BLENDER_EEVEE`** — 4.x의 'BLENDER_EEVEE_NEXT'는 enum에 없음(TypeError). GTX1650에서 헤드리스 EEVEE 렌더 정상(512px 4장 수 초).
- **카메라 조준은 TRACK_TO 제약**(빈 오브젝트 타깃) — 시선 오일러 수작업은 축이 뒤집힘.
- ⚠️**팔·부속 배치는 '피벗+방향벡터'로 계산하고 회전 부호를 렌더로 검증** — rot Y 부호 실수로 팔이 어깨 위로 삐죽(v1·v2 연속 실수, 렌더 눈검수가 잡음). 원통 축=(sinθ,0,cosθ), 아래-바깥 방향은 θ=-sx*angle.
- **두 색 알약 몸통**: 조각 4개(원통+반구) 잇지 말 것 — 이음새 음영 줄. **단일 UV구 타원체 + 면 중심 z로 material_index 분기**(로컬 좌표 기준)가 매끈.
- 검수 렌더에 **바닥 평면(그림자)** 필수 — 없으면 붕 떠 보여 비례 판단이 안 됨. sun.data.angle로 그림자 부드럽게.
- FBX 내보내기 기본 애드온으로 됨(`export_scene.fbx`, FBX_SCALE_ALL). 유니티 반입은 다음 단계(실기 미검증).

## RED 탐험가 실전 조형 (도안 기반, v1→v4)
사용자 도안 `Downloads\도안.png`(Pill Agents Coop 4종 팩 — RED 탐험가·BLUE 전술가·YELLOW 엔지니어·GREEN 과학자, 로우폴리·순수 알약 몸체·LED 스크린 얼굴=이모지 커스텀이라 빈 화면) 기준. 결과물 Desktop\알약요원_블렌더테스트\red_agent4.{fbx,blend,py}+렌더 4장. **COLOR 상수 한 줄 = 4색 팩**(아직 RED만 뽑음).
- ⭐**AgX 함정**: 블렌더 4.x/5.0 기본 톤매핑(AgX)이 채도 높은 빨강을 분홍으로 물빠지게 함 — 스타일라이즈드는 `scene.view_settings.view_transform = 'Standard'`.
- ⭐**한 덩어리 캡슐**: uv구 정점을 위아래로 벌려(z±STRETCH) 캡슐화 + **bmesh.ops.bisect_plane으로 경계 높이에서 절단** 후 면 중심 z로 material_index — 색 경계선이 벽면 임의 높이에 깔끔하게 생김(벽 쿼드가 세로로 길어 절단 없이는 경계가 안 섬).
- ⭐**곡면 위 평판 함정(양쪽 다 실측)**: 얕게 심으면 판 옆면이 들뜨고, 깊게 심으면 **곡면이 판 가운데를 뚫고 나옴**(스크린 중앙에 빨간 마름모). 정답 = 중앙이 표면보다 아주 살짝 앞(0.03~0.05)에 오는 깊이 — 들뜬 모서리는 '베젤'로 읽혀 오히려 좋음. 부착물(스위치 등)의 y는 반드시 `sqrt(R²-x²)`로 표면 좌표 계산(안 하면 떠 다님).
- 로우폴리 각면 = 플랫 셰이딩 기본값 그대로(smooth 안 걸면 됨) + SEG 16. UV는 join 후 smart_project. FBX는 use_selection으로 요원만.

## 리깅 검증 완료 (red_agent_rigged, 같은 날)
사용자가 코드 조형 품질에 불만("모델링 맘에 안 듦") → **분업 확정 방향: 모델링=사용자(아트 담당), 리깅·내보내기=클로드.** 리깅 실력 증명 데모 통과.
- **강체 파츠 리깅은 코드가 정확**: 본 10개(Root>Body>Arm.L/R>Hand.L/R, Leg.L/R>Foot.L/R), 파츠→본 1:1 정점그룹(weight 1.0). ⭐**join 전에 각 파츠에 본 이름으로 vertex_groups.new+add — join이 이름별로 그룹을 합쳐줌**(웨이트 페인팅 0). Armature 모디파이어+parent.
- 포즈 검증: 인사(Arm.R Z-150°+Hand 꺾기+Body 기울임)·걷기 중간(다리 X±25~30·팔 반대 스윙) 렌더로 어깨 찢어짐·발 미끄러짐 없음 확인. ⭐본 축이 아래(head→tail=-Z)라 옆으로 들기=Z회전 — **부호는 계산 말고 렌더로 검증**(모델링 팔 부호 실수의 교훈 재적용).
- FBX: add_leaf_bones=False(유니티 Generic 리그 깔끔). 사용자 메시를 받으면 같은 리그 구조 이식 가능 — 파츠가 분리돼 있거나 이름만 알려주면 됨. Desktop\알약요원_블렌더테스트\red_agent_rigged.{fbx,blend,py}+포즈 렌더 5장.
- 유기적 스킨 변형(부드러운 팔꿈치)은 자동 웨이트+눈검수 반복 필요 — 이 게임 설계(기계식 관절)에선 불필요하다고 사용자에게 고지함.

## 회복 앰플 소품 조형 (2026-07-16 세션57)
사용자가 도구 모델링(Desktop\알약게임\에 drill·gun·injector·shild·player.blend 등 직접 작업 중) 하다가 **"회복 앰플 만들어볼래?" 직접 요청** — '모델링=사용자' 분업의 예외(단순 소품은 클로드에 맡김). ⭐**회전 대칭 소품(병·앰플·탄약 등)은 코드 조형이 강함**(캐릭터 조형 불만과 달리 결과 만족스러움) — 프로파일 회전이 매끈해서.
- 기법: **프로파일(반지름,높이) 점열 → Screw 모디파이어 360° 회전 → apply**가 매끈한 병 실루엣의 정답(원통 잇기보다 나음). 유리는 Solidify 0.012로 벽 두께.
- 구성: 유리 셸(Principled Transmission 1.0·IOR 1.45·Roughness 0.03) + **발광 회복액**(Emission 초록, str 2.2 — 유리 청틴트와 섞여 시안-그린으로 나옴, 회복/에너지로 잘 읽힘) + 금속 목 칼라(torus) + 밀봉 첨단. 높이 ~0.9유닛(injector 도구 1.8의 절반=손에 드는 병 비례).
- ⚠️**유리·발광은 Cycles가 정답**(EEVEE 유리 설정 함정 회피). CPU·110샘플·640x720·4뷰 = **약 4분**(뷰당 ~1분, 120초 Bash 타임아웃 넘겨 백그라운드행 — 무거운 Cycles는 처음부터 run_in_background 권장). view_transform='Standard'(AgX 물빠짐 방지).
- 결과물 `Desktop\알약게임\ampoule.{blend,fbx}` + ampoule_preview_1~4.png. FBX는 bake_space_transform=True·-Z fwd·Y up·FBX_SCALE_ALL(유니티 바로 반입). 사용자 리뷰 대기(색/비례 조정 가능).
